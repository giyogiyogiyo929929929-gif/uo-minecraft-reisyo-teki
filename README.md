# Civ Tactics(仮) — 仕様書 README

Minecraft Bedrock (Script API) 上で動く、Civilization風のターン制・タイルベース戦略ゲームアドオン。
スーパーフラット上にマスを生成し、複数プレイヤー(または1人のOPが操作する複数のテスト国家)が
領土・都市・生産・研究・外交・戦闘を行い、最後まで生き残った国家(または同盟)の勝利を目指す。

このドキュメントは **現時点の実装仕様のスナップショット** です。コードが正なので、齟齬があれば
実装(各 `.js` ファイル)を優先してください。

## 1. 全体の流れ

1. OPが `/civ:generate <幅> <高さ>` でマップを生成する(単位はマス数。1マス5×5ブロック)。
2. 各プレイヤーが `/civ:join` でゲームに参加する。
3. OPが `/civ:start` でゲームを開始する(参加者全員の研究/文化/外交/首都フラグ/宗教/戦略資源
   (石油・鉄・馬・ゴールド・石炭・ウラン)の在庫、CO2累計排出量(§24)がリセットされる。
   勝利ポイントだけはリセットされない)。
4. 各プレイヤーは自分のターンに、領有・都市建設・生産・研究・移動・戦闘・外交などを行い、
   `/civ:endturn` で次の人に手番を渡す。
5. いずれかの勝利条件(§16)を満たすとゲームが自動的にリセットされ、次のゲームに備える。

## 2. マップとマス

- 1マス = 5×5ブロック(`TILE_SIZE = 5`)。マスの中心付近に地形・資源ブロックが配置される。
- 地形タイプ(生成時の重み付き抽選。川・海・池・湖は特殊生成ロジックで後から決まる)。
  下表の重みは既定値であり、**OPはメニュー(「§e[Settings] マップ生成の設定」、§18)から
  各バイオームの生成有無・重みを変更できる**:

  | 地形 | 重み | 備考 |
  |---|---|---|
  | 草原 (grassland) | 22 | |
  | 森林 (forest) | 16 | 伐採可能・木が生える |
  | 砂漠 (desert) | 12 | |
  | 寒冷地 (cold) | 12 | |
  | 山 (mountain) | 10 | 中央が盛り上がった地形 |
  | 熱帯雨林 (rainforest) | 10 | 伐採可能・大きい木が生える |
  | 海 (sea) | 10 | 生成時にシード状に配置 |
  | 川 (river) | 8 | 海に繋がらない川は「池」になる |
  | 池 (pond) | 0 | 川の余り。3マス以上繋がると「湖」に昇格 |
  | 湖 (lake) | 0 | 池が3マス以上繋がった結果 |
  | 山脈 (mountainRange) | 0 | 山が隣接4方向で2マス以上繋がった結果。**どのユニットも進入不可**、都市も建設不可 |

- **地形と移動の制約**(`isWaterTerrain`/`isImpassableTerrain`, `mapGen.js`):
  - 海・川・池・湖は「水上マス」。**海軍ユニット(`domain: "naval"`)しか進入できない**。
  - それ以外の通常地形は「陸地マス」。**陸軍ユニット(`domain: "land"`、既定値)しか進入できない**。
  - 山脈だけは陸軍・海軍問わずどのユニットも進入できない、純粋な障害物マス。
  - **都市・施設・区域は、定義側で明示的に許可(`allowWater: true`)しない限り水上マスには
    建設できない**(既定では全て陸地マス限定)。現状 `FACILITY_DEFS`/`DISTRICT_DEFS` に
    `allowWater: true` を指定した項目は無いため、施設・区域は常に陸地マス限定。首都を含む
    都市(`/civ:settle`)は水上マスに建設不可(山脈と同様のエラーになる)。
- 資源(既定25%の確率で、対応する地形に1つ配置。カテゴリ: 戦略/高級/ボーナス。
  出現率はOPがメニュー(§18)から変更できる):
  鉄・石炭・ダイヤモンド・金・小麦・魚・石油・隕石・魔晶石・月の石・ウラン(238)・馬(草原限定)。
  石油・石炭・ウランは、資源があるマスが労働者に割り当てられていれば毎ターン自動でそれぞれの
  収入になる(施設不要。§6・§24参照)。鉄・馬は資源があるだけでは収入にならず、それぞれ対応する
  施設(鉄は「鍛冶場」、馬は「牧場」。いずれも§9)をそのマスに設置して初めて収入になる。
  ダイヤモンド・金・魔晶石・月の石(高級カテゴリ)は、労働者が割り当てられていれば毎ターン
  ゴールド+3になる(施設不要。§23)。兵種「cavalry」系のユニット(騎兵・騎士)の生産完了時に馬を1個、
  「鉄を使う」ユニット(剣士・銃士・大砲)の生産完了時に鉄を1個、戦車・戦艦の生産完了時に石油を1個、
  ミサイル・対空砲の生産完了時にウランを1個消費する(いずれも§8)。石炭火力/石油火力/原子力発電所も
  それぞれ石炭/石油/ウランを毎ターン1消費する(§24)。隕石は戦略カテゴリのため生成時の基礎生産力に
  下駄が乗るのに加えて、施設「隕石クレーター採掘場」(§9)を設置すると毎ターン生産力+6・
  科学力+2になる。
- マップの外周には黒曜石の壁が生成され、境界線を示す。
- **シミュレーション範囲外のマップ生成に対応**: 生成範囲がプレイヤーのシミュレーション範囲
  (既定の仮定値 `ASSUMED_SIMULATION_RANGE_BLOCKS = 128` ブロック)を超える場合のみ、生成中に
  小さく分割した `tickingarea` を一時的に張り直しながら進める(範囲内なら使わない)。
  各バンド(既定4×4マス)ごとに「読み込み確認 → 設置 → 実際に置けたか検証 → (失敗時)個別リトライ」
  を行うため、時間はかかるが安定して生成できるように作られている(`mapGen.js`)。

## 3. 国家(civ)とソロテスト

- 通常は「1実プレイヤー = 1国家」。
- OP(オペレーター)は `/civ:addciv [名前]` で**テスト国家(仮想国家)** を追加でき、
  `/civ:switchciv` で「今操作している国家」を切り替えながら1人で複数国家を動かせる
  (ソロテスト用)。テスト国家は世界に実体を持たず、研究・外交などのデータは
  world側にID別の名前空間で保存される。
- コマンド・メニュー操作はすべて「今操作中の国家」として実行される。物理的な移動・ブロック設置は
  OP自身の体で行う(一人二役)。
- OPは `/civ:addbot [名前]`(またはメニューの「国家管理」→「Botを追加する」)で**Bot**を
  追加できる。Botもテスト国家と同じく世界に実体を持たない仮想国家だが、テスト国家と違って
  **人間が操作(switchciv)する必要が無く、毎ターン自動で行動する**(§3-1参照)。
  ゲーム開始前であれば追加と同時に自動でゲームへ参加する。

### 3-1. Bot(自動操作国家)

`bots.js` が担当。Botは既存のコマンド関数(領有・都市建設・開拓権取得・生産開始・施設設置・
区域着工・戦闘ユニットの移動/攻撃/都市占領など)を、「決定した目標マスに立っているプレイヤー」
または明示的なtx,tz引数を模した擬似オブジェクト経由でそのまま呼び出す。そのため、Botの行動は
人間が手動で行った場合と全く同じ条件判定・コスト・副作用を通る。

**「脅威」の判定**: 自国の都市の近くにいる、外交協定の無い敵ユニットの**戦闘力の合計が20
(戦士1体分)を超える**場合、そのターンは「脅威あり」と判定する(`computeThreatLevel`)。
素通りするだけの単独ユニット1体では経済(生産・拡張・研究)を防衛優先へ切り替えず、
まとまった戦力が近づいて初めて反応する。この1つの判定を、拡張・生産・研究の3つの判断に
横断的に使うことで、「危険な時は防衛、安全な時は経済成長」という一貫した優先順位の
切り替えを表現している。警戒すべき距離は相手との関係によって変える: **戦争状態の相手は
半径6マス**(実際に領土へ侵入・攻撃してくる可能性があるため)、**「関係なし」の相手は
半径2マス**(宣戦布告されない限り領土に入って来られず実害が無いため、余程近づかない限り
警戒しない)。不可侵条約・同盟の相手はそもそも脅威に含めない。

毎ターン(自分の手番が回ってきた瞬間に自動実行され、完了すると即座に次の手番へ進む):

1. 都市が1つも無ければ、空きマス(資源があれば最優先、次に**狭くない水域に隣接する
   沿岸のマスを優先**)に最初の都市(首都)を建てる(この場合、他の行動はせずターンを終える)。
2. 脅威が無く、開拓権があれば、自国の空き領地マス(**既存の自国都市から4マス未満の
   近すぎる場所は候補から除外した上で**、資源、次に沿岸を優先)に新都市を建てる
   (1ターン1つまで。脅威がある間は拡張より防衛を優先し、新都市の建設を見送る)。
   **沿岸に都市を建てることで、その都市が帆船(§8)を生産できるようになる**(下記7.参照)。
3. 自国の領地に隣接する未所有マス(資源があれば最優先、次に**狭くない水上マスを優先**)を、
   コストが賄える範囲で領有する(最大3マス/ターン)。**連結する水上マスが3枚未満の狭い水域
   (1〜2マスの池・短い川の切れ端など)は、領有の候補にすら含めず無視する**(拠点として
   活用しにくいため)。それ以外の水上マス(海・広い川など)は、資源マスに次ぐ優先度で
   積極的に領有する(食料・生産力などの通常の産出に加え、沿岸都市であれば§8の帆船の
   生産にも繋がる)。
4. 首都の人口に余裕があれば開拓権を取得する。
5. 空き領有マスがあり、その帰属都市が区域(専用建造物含む)を建設中でなければ、技術条件を
   満たす区域(聖地・工業地帯)、または完成済みの区域の上に区域専用建造物(社)の建設を開始する。
   都市1つにつき同時に1つまでという制約はそのまま守る。**新規着工の場合、同じ都市に候補マスが
   複数あれば、隣接ボーナス(§12)の合計値が最も大きいマスを選ぶ**(条件を満たす最初のマスに
   無条件で着工する以前の実装だと、質の低いマスに建ててしまうことがあったための改善)。
6. 空き領有マスがあれば、技術・資源条件を満たす施設(採石場・鍛冶場)を、労働者の行動回数が
   続く限り設置する。**複数の候補マスがある場合、隣接ボーナス(§12)の合計値が大きいマスから
   優先して設置する**(行動回数を使い切っても質の良いマスから埋まるようにするため)。
7. 生産中でない都市があれば、**脅威があり、かつ都市数に見合った戦力(近接+遠距離ユニットの
   合計が都市数×3未満)にまだ達していなければ**、近接・遠距離のうち数が少ない方(同数なら
   遠距離)のカテゴリを優先し、**そのカテゴリの中で今生産可能な最も戦闘力の高いユニット**を
   選んで生産する(近接・騎兵・対騎兵系ユニットを戦闘力降順にまとめた「近接系」優先順位:
   戦車>近代歩兵>銃士>剣士>騎士>長槍兵>槍兵>騎兵>戦士、遠距離・攻城系ユニットを同様に
   まとめた「遠距離系」優先順位: 機関銃兵>近代砲兵>重装弓兵>大砲>カタパルト>弓兵。
   前提技術・社会制度が無ければ自動的に下位ユニットへフォールバックする。常に同じユニットだけを
   作り続けないための調整)。それ以外(脅威が無い、またはもう十分な戦力がある)は
   労働者(3人未満なら優先)・穀物庫・交易所・市場・オベリスク・訓練場・防壁・近接系ユニット・
   遠距離系ユニット(いずれも上記と同じ優先順)の優先順で、条件を満たす最初の生産物を
   生産キューに入れる。**沿岸都市(隣接マスに水上マスがある)であれば、沿岸都市数に見合った
   隻数(沿岸都市1つにつき最大2隻が目安)の海軍ユニットをまだ持っていない限り、交易所の直後
   (市場・オベリスク・訓練場・陸軍ユニットより前)に海軍ユニット(産業化を取得済みなら戦艦、
   無ければ造船術取得済みで巡洋艦、どちらも無ければ帆船)を割り込ませて優先的に生産する**
   (末尾に追加すると他の生産に押し出されて事実上作られなくなるため、あえて中盤の優先度に
   してある。内陸都市では配置できないため選択肢に含めない)。
   **戦争中は、都市1つにつき1基までの対空砲(§17。ミサイル迎撃)と防壁(§13)を、穀物庫の
   直後(交易所・市場・オベリスク・陸軍ユニットより前)に割り込ませる**(それぞれ既に
   保有済みの都市は自動的に対象外になる。平時は無駄になりうる出費を避けて経済を優先する
   ため対象に含めない)。経済・海軍・対空砲のいずれも生産すべきものが無く、**戦争中で、
   かつミサイルの備蓄が上限(2発)未満なら**、最後の選択肢として都市を一撃で破壊できる
   ミサイル(§17)を生産する。
8. 研究・社会制度が未選択なら、**脅威がある間は弓術・青銅器・騎乗・石工術・火薬・冶金術・
   産業化・電力・ロケット工学など軍事技術を優先**し、無ければ陶磁器・占星術・航海術・貨幣経済・
   教育など経済・成長寄りの技術を優先して、条件を満たす最初の項目を自動選択する(優先順位
   リストに無い項目も、リストを使い切った後に自動的に拾われるため、いずれの技術・社会制度も
   取りこぼされない)。社会制度は「法典→使節団→政治哲学→商業→外交→軍制改革→神権政治→
   封建制度→騎士道」のおおよその優先順位(封建制度→騎士道は、社会制度が直接ユニットを
   解放する初めての例)。
9. 届いている外交提案は全て承認する(自国にとってノーリスクなため)。その後、他の全国家との
   関係(同盟は対象外)をそれぞれ判定する:
   - **既に戦争状態の相手は、相手の国力が自国の2.5倍を超えていれば(圧倒的に負けている)、
     自分から講和を提案する(相手の承諾が必要)。** 宣戦布告の閾値(1.8倍、後述)よりあえて
     大きくしてあり、宣戦布告した瞬間に相手がすぐ講和を提案して戦争が実質発生しなくなるのを防ぐ。
   - **自国より明らかに弱い(相手の国力が自国の国力÷1.8以下)「関係なし」の相手には**、
     次の3条件を**すべて**満たす場合のみ自分から宣戦布告する(征服を狙う。社会制度・
     試合の設定を問わず常に行える): **(1)既に他の誰とも戦争中でない**(二正面作戦の回避。
     既に1つ戦争を抱えている間は、たとえ弱い相手が見つかっても新たな戦線を開かない)、
     **(2)ゲーム開始から10ターン以上経過している**(序盤の未成熟な国力差——都市を1つ多く
     持っているだけ、等——による即開戦を防ぐ猶予期間)、**(3)相手の領有マスが自国の
     領有マスから20マス以内にある**(地理的に接点の無い遠方の国家への無意味な宣戦布告を
     防ぐ、簡易な「国境を接しているか」判定)。
   - **自国より明らかに強い(相手の国力が自国の1.2倍以上)相手には**、社会制度の条件
     (使節団/外交)と試合の設定を満たしていれば、自分から不可侵条約→同盟の順で関係を
     提案する(段階を踏む)。
   - どちらでもない(強すぎず弱すぎない)相手には何もしない。
   国力は「都市数×10+全戦闘ユニットの戦闘力合計」。
10. **宗教**(§11参照): 宗教を未創始で、条件(聖地を1つ以上保有・国家全体の信仰力が100以上)を
    満たしていれば創始する。創始済みなら、購入条件(社/大聖堂/審問の開始状況)を満たし、
    実際の購入コスト(購入するたびに+30)を賄える都市があれば宗教ユニットを購入する
    (伝道者・使徒・審問官のいずれも対象)。自国の宗教ユニットごとに、次の優先順で行動する:
    a. **攻撃可能(使徒・審問官)なら**、隣接する敵(同盟関係の無い)の宗教ユニットがいて
       今ターンまだ攻撃していなければ最優先で攻撃する(反撃なしの一方的な攻撃。布教・弾圧
       とは独立してカウントするため、同じターンに両方行うこともある)。
    b. **使徒は**、審問が未開始かつ布教力が満タン(=一度も布教していない)なら審問を開始する
       (一度きりの特殊能力。国家全体が以後審問済みになり審問官を購入可能になる、長期的な
       価値の高い投資と判断し、機会があれば即座に行う。この使徒自身は消滅する)。
    c. **布教可能(伝道者・使徒)なら**、隣接(マス距離1)する都市があり今ターンまだ布教
       しておらず布教力が残っていれば布教する(複数隣接していれば、自国の宗教がまだ主流
       でない都市を優先する)。
    d. **弾圧可能(審問官)なら**、今立っているマスが何らかの都市の領地(所有者問わず)に
       属していれば、布教力を1消費してその都市の自国以外の宗教の圧力を80%削減する。
    e. それ以外は、自国・他国問わず全都市の中から、自国の宗教がまだ主流でない都市を
       最優先目標として、そこへ向けて移動する(無ければ最も近い都市)。**宗教ユニットは
       地形・所有者を問わずどこへでも移動できる仕様(§13参照)のため、戦闘ユニットのような
       8方向の経路探索は行わず、移動力の範囲内(直進である必要も無い)で目標に最も近いマスを
       単純に総当たりで選ぶ。**
    宗教ユニットが撃破されると、最寄りの都市(所有者問わず)の宗教的圧力が撃破した側+1000/
    撃破された側-1000変動する(§11)。
11. **戦争中で、ミサイルの在庫がある都市が1つでもあれば**、敵都市へ向けてミサイルを1発
    発射する(§17。都市を一撃で消滅させる切り札のため、1ターンにつき最大1発しか発射しない)。
    標的は**対空砲(§8)の無い都市を最優先**し(対空砲のある都市を狙うと迎撃され無駄撃ちに
    なりやすいため)、その中でも相手の首都を優先する(対空砲の無い首都 > 対空砲の無い
    一般都市 > 対空砲のある首都 > 対空砲のある一般都市の順)。
12. 自国の戦闘ユニットごとに、次の優先順で1つだけ行動する。**近接ユニット(戦士等)を
    遠距離ユニット(弓兵等)より先に処理する**ことで、同じターン内で戦士が前進した後の
    盤面を弓兵の移動判断(h)が踏まえられるようにしている。
    a. **戦争状態の**無防備な敵都市(都心のHPが既に0)の上に立っていて今ターンまだ行動して
       いなければ占領する。
    b. **同じマスに敵(同盟関係の無い)の宗教ユニットがいて、移動力が満タン(今ターンまだ
       他の行動を取っていない)なら、異教徒として排除する**(§11「異教徒の排除」
       `cmdPurgeHeretic`。移動力を全て消費して一方的に消滅させる、確実に成功する行動のため、
       成否がランダムな攻撃(c)より先に判定する)。
    c. 攻撃範囲内に**戦争状態の**敵ユニットがいれば、まず**今の攻撃力(包囲ボーナス込み)で
       最低ダメージロールでも確実に撃破できる相手**を最優先で狙う(中途半端に複数体を
       削るより確実に数を減らす)。確実に倒せる相手が複数/皆無なら、その中で**包囲ボーナス
       (§13。その相手に既に隣接している味方ユニットの数)が最大の相手を優先し、同数なら
       HPが最も低い相手**を攻撃する(「関係なし」・不可侵条約・同盟の相手は攻撃対象に含まない)。
    d. 攻撃範囲内に敵ユニットはいないが**戦争状態の**敵都市があれば、**都心のHPが最も
       低い都市を優先して攻城する**(§13。都心はHPを0にしない限り占領できないため、
       これが無いとBotは都市を一切陥落させられない)。
    e. **HPが35%未満まで減っていれば**、最寄りの自都市へ撤退する。
    f. 自都市の上で守備中なら、**戦争状態の**敵が半径6マス(脅威判定と同じ距離)以内に
       近づくまで持ち場を離れず待機する(このときHPが減っていれば、行動力を消費してその場で
       休息しHPを30%回復する)。
    g. **自分は健在で、近く(4マス以内)に撤退中の負傷した味方がいれば(かつ最寄りの敵と
       同じかそれ以上に近ければ)、敵を追うより先にその護衛(合流)へ向かう**(単独で撤退する
       負傷ユニットが道中で各個撃破されるのを防ぐ。撤退先は毎ターン最新の味方位置から
       再計算するため、合流後は自然と味方の撤退先(自都市)へ追従する形になる)。
    h. それ以外は最も近い**戦争状態の**敵(ユニットまたは都市)へ向けて移動する
       (「関係なし」の相手は宣戦布告されない限り領土に入って来られず攻撃もできないため、
       追跡・接近の対象にもしない)。**ただし遠距離ユニットは、自軍に近接ユニットがいるにも
       関わらず自分の方がその全員より敵に近づいてしまう場合、前進を控えてその場に留まり
       近接ユニットが追いつくのを待つ**(弓兵が戦士より先に単独で敵地へ突出して各個撃破
       されるのを防ぐ簡易な隊列判断。近接ユニットが1体も無ければ待機せず通常通り前進する)。
       移動先は、周囲8方向それぞれについて今の移動力で進める最も遠いマスを求め、その中で
       目標までの距離が最も縮むマスを選ぶ(1手先読みの貪欲法による簡易な経路探索)。
       **各方向とも、進行方向に1マスずつ辿りながら経路上の全マス(通過点も含む)が
       進入可能かを確認し、最初に塞がったマスの手前までしか進めない**(移動力2以上の
       ユニット(帆船など)が、間に挟まる陸地を飛び越えて別の水域へワープしてしまう
       ことはない)。直進ルートが他国の領土(§15)・水上/山脈マス・他ユニットで
       塞がっていても、別方向から迂回できるならそちらを選べる。**この探索(撤退・護衛・追跡いずれの
       移動判断でも共通)が3ターン連続で失敗した(近づける移動先が1つも無かった)
       ユニットは、以後は目標に近づかない移動(横移動・後退)も許可して再挑戦する**
       (`unit.stuckTurns`で連続失敗数を数える、`attemptMove`)。移動に成功すると
       カウンタは0に戻る。迂回しても回り込めない完全な袋小路でない限り、これで
       数ターン以内に動き出せる。

全参加者がBotの場合でも、手番は自動でどんどん進み続ける(`advanceUntilHuman()` が人間の
手番になるまでBotの手番をまとめて処理する)。ただし「Bot→Bot」と連続する手番の間には
間隔(tick)を置き、Bot同士の対戦が観戦できないほどの速度で一瞬に終わってしまわないように
している(人間の手番の直前に来る最初の1手にはこの遅延は挟まらない)。この間隔は試合の設定
(§18、既定5tick=0.25秒)からOPがいつでも変更できる(`getMatchSettings().botTurnDelayTicks`)。

## 4. ターン制

- `playerOrder` に参加順で並び、順番に手番が回る。
- 自分のターン開始時に:
  - 全戦闘ユニットの移動力が回復する。
  - 各都市の産出量(食料・生産力・石油・信仰力・鉄・馬・ゴールド・石炭・ウラン)が計算され、食料消費・人口成長・飢餓判定が行われる。
    ゴールドの維持費差し引き・破産による強制解散も、このタイミングで行われる(§23)。
  - 人口1人につき科学力・文化力が1ずつ加算される(進行中の研究/制度に充当、無ければ繰越)。
  - 勝利条件の判定が行われる(§16)。

### 途中離脱への対応

誰かがゲーム途中で抜けても進行が止まらないよう、三重の対策が入っている。

1. **手番のプレイヤーが退出した瞬間に自動スキップ**(`main.js`, `playerLeave`イベント)。
   ちょうどそのプレイヤーの手番だった場合、即座に次の操作可能な国家へ手番が進む。
2. **手番が回ってきた時点でオフラインなら自動スキップ**(`endTurn`/`startGame`共通)。
   実プレイヤーは本人がオンラインか、テスト国家(仮想国家)は操作者(controller)がオンラインか
   で判定する(`isCivControllable`, `civs.js`)。参加者全員がオフラインの場合はそこで待機し、
   誰かが復帰した時点のターン処理で自動的に再開する。
3. **OPによる強制スキップ**: `/civ:forceendturn`(またはメニューの【管理者】手番を強制スキップ)。
   オンライン表示のままフリーズ・無応答になった等、自動判定でカバーしきれない場合の保険。

## 5. 領有・都市

### 領有 (`/civ:claim`)
- 自分の都市または既存の領地に隣接する未所有マスのみ領有できる。
- コスト: 最寄りの自都市の人口 -1。
- 領有したマスの中心には、領有した国家の色(`getPlayerColor`)の羊毛で作られた旗(のぼり旗、
  水上マスなら水面を染めるだけ)が立つ(`placePlayerBannerAtCenter`, `commands.js`)。

### 都市の建設 (`/civ:settle`)
- 足元のマスが自分の領地であれば都市を建設できる。
- **首都は生涯で1度だけ自動設置される**。一度でも首都を持ったことがある国家
  (`civ:hasFoundedCapital` フラグ)は、都市を全て失っても `/civ:settle` で自動的に
  新しい首都は立たない(通常の都市になる)。首都を取り戻すには、既存都市で「遷都」
  (§8, `capital`)を生産する必要がある。
- 初めての首都は無料。それ以外の都市は「開拓権」を1消費する
  (`/civ:buyrights`: 首都人口2を消費して開拓権+1、人口3以上必要)。
- 淡水(川/池/湖)に隣接: 住宅上限5。海に隣接: 住宅上限3。どちらも無し: 住宅上限2。
  さらに、周囲8マスに(不可侵条約も同盟も無い)敵国の領地が隣接していると住宅上限-1
  (国境ペナルティ)。
- 初期人口: 首都2・通常都市1。初期労働者: 首都1人・通常都市0人。
- **首都マスの最低ベース産出量保証**: 首都を建てたマスの基礎食料産出量・基礎生産力産出量
  (`foodYield`/`productionYield`)が、それぞれ2以下だった場合は3まで引き上げられる
  (ランダム生成で弱い立地に首都を建ててしまい詰むのを防ぐための保証。他の通常マスは対象外)。

### 遷都
- 生産物「遷都」(`capital`, cost 100)を**首都以外の都市でのみ**生産できる。完成すると、
  その国家が持っていた旧首都の首都フラグを外し、この都市が新しい首都になる。

### 都市の占領
- 移動力が満タンの自国ユニットが敵都市のマスにいるとき、メニューから占領できる。
  **都心のHPが0を超えている間、敵ユニットはそもそもそのマスへ移動できない**(§13)ため、
  実質的な流れは「攻撃で都心のHPを0まで削る → 空いたそのマスへ移動する → 次の自分のターンで
  占領する」という2段階になる。
- 占領すると、その都市に帰属していた領有マス(および、そこに設置された施設)も同時に
  占領側へ移る。**占領した都市はそのまま首都にはならない**(首都フラグは占領時に必ず解除)。
  都心のHP・防壁のシールドHPは満タンに戻る(防壁自体は破壊されず引き継がれる。§13)。
- **占領した都市・帰属マスの旗(のぼり旗)は、即座に占領した自分の色へ塗り替わる**
  (`placePlayerBannerAtCenter` を占領側の色で呼び直す。物理的なブロックの高さは、
  そのマスが元々どう建設されたか(首都/通常都市/通常領地)に合わせて調整される)。

### 都市の破壊
- ミサイル着弾、または3ターン連続飢餓による人口0での崩壊で、都市は完全に消滅する
  (オーナー無しの中立マスに戻る)。

## 6. 人口・住宅・食料・成長・飢餓

- 毎ターン、市民配置システムが「[Food]+[Prod]の合計が高いマスから順」に、人口の数だけ
  領有マスを自動で「働かせる」(それ以外の領有マスの産出は無視される)。
- 石油資源のあるマスが働かされていれば、毎ターン石油+1。鉄・馬は施設・区域のボーナス経由で産出される
  (下記「産出量の倍率」参照。馬は施設「牧場」が資源「馬」のあるマスにある場合のみ産出される)。
- 法典(civic)取得済みなら食料+1、穀物庫(building)があれば食料+1、
  建造物・施設・区域の隣接ボーナス(§12)もここで加算される。
- 食料消費 = 人口 + (生産中の物の `extraUpkeep`。例: 交易所建設中は+1)。
- 食料が足りない場合、飢餓ターンが+1。3ターン連続で飢餓が続くと人口-1(飢餓ターンはリセット)。
  人口が0になった都市は崩壊(消滅)する。
- 食料が十分な場合、貯留量が成長閾値(`10 + (人口-1)×2`)に達すると人口+1
  (住宅上限に達していれば成長は停止する)。

### 産出量の倍率(バランス調整・OPが試合の設定で変更可能)

`turns.js` の `getCityCurrentYields()` は、都市の毎ターン産出量(食料・生産力・石油・信仰力・鉄・馬・ゴールド・石炭・ウラン)を
集計する**最後の1箇所**で、合計値に倍率を掛けている。マス固有の基礎産出量(働かせているマス分)、
施設/区域/建造物のflatYields・隣接ボーナス、人口比例ボーナス、穀物庫/オベリスク/社/法典などの
個別ボーナスまで、**この関数が集計するものすべてが対象**。そのため、以下の各セクション
(§8〜§12)に書かれている数値(例: 「オベリスク: 信仰力+4」)はコード上に定義された**基礎値**
であり、実際に都市が受け取る産出量はそれに倍率を掛けた値になる。交易所のルートボーナス
(§8の交易所)も同じ倍率がかかる。

この倍率は既定で`2`だが、メニューの「§e[Settings] 試合の設定」(OP専用、§18)からいつでも
変更できる(`state.js` の `getMatchSettings()/setMatchSettings()`。値は`civ:matchSettings`
というDynamic Propertyに保存され、**ゲームリセットを跨いでも保持される**)。

### 信仰力

- 都市は**人口1につき信仰力+1(基礎値)**を毎ターン産出する(働かせているマスの数とは無関係。
  食料/生産力とは違い、都市の人口そのものから算出される)。
- オベリスク(§8)・聖地(§10)・社(§10)を持つ都市は、それぞれの表に書かれた基礎値ぶん
  信仰力が追加される(いずれも上記「産出量の倍率」の対象)。
- 消費は無く、産出ぶんがそのまま都市ごとの `faithStorage` に貯留され続ける。
  用途: 宗教の創始(国家全体で100必要。§11)、伝道者の購入(都市ごとの貯留分を使用。§11)。

## 7. 労働者と行動回数

- 労働者は「人数」ではなく「行動回数プール」(`city.workerUnits`)で管理される。
- 労働者1人につき行動回数は `WORKER_ACTIONS_PER_UNIT = 3`。
- 労働者を消費するアクション(伐採 `/civ:chop`、施設の設置 `/civ:install`)は、
  労働者を丸ごと1人消費するのではなく、**行動回数を1減らす**。行動回数が0になった
  労働者だけがプールから取り除かれる。
- 都市の生産で「労働者」(cost 10)を作ると、新しい労働者(行動回数3)が1人追加される。

## 8. 生産(建造物・ユニット)

- 各都市は同時に1つだけ生産できる(`city.production = { id, progress, cost }`)。
- 毎ターン、その都市の産出生産力ぶんだけ `progress` が加算され、`cost` に達すると完成する。
- 中止(`/civ:cancelbuild`)しても、蓄積した進行度は消滅せず次の生産に持ち越される
  (`productionCarry`)。
- 戦闘ユニットが完成するとき、都市のマスに既に別の戦闘ユニットがいる場合:
  - 敵(自国でも同盟国でもない)なら生産は中止される(進行度は保持)。
  - 自国/同盟国のユニットなら、周囲8マスの空いているマスへ自動で退避配置される
    (空きが無ければこの場合も中止)。
- **陸軍/海軍ユニット**: 各ユニットは `domain: "land"`(陸軍、既定値)または `domain: "naval"`
  (海軍)を持つ。陸軍ユニットは都市自身のマス(常に陸地)にそのまま配置されるが、海軍ユニットは
  都市に**隣接する水上マス**(海・川・池・湖)にのみ配置される(隣接する水上マスが無い内陸都市
  では生産完了時に中止される。進行度は保持)。
- **空軍ユニット**(`domain: "air"`): マスには配置されず、その都市の**航空基地**(§25)に空き枠が
  あれば配置される。空き枠が無ければ生産完了時に中止される(進行度は保持)。

### 世界遺産について(新要素)

ピラミッド・大灯台は通常の建造物(`category: "building"`)に汎用フィールド`isWonder: true`を
足しただけの存在で、効果自体(`flatYields`)は市場や訓練場と全く同じ経路(`getFlagFlatYields`)
で自動加算される。異なるのは**1ゲームにつき1国家しか着工できない**という制約で、
`state.js`が国家をまたぐワールド単位のDynamic Property(`civ:wonderClaims`、
`{ [遺産ID]: 着工した国家のID }`)で管理する:

- ある国家が着工した瞬間(`cmdStartProduction`)にその遺産は**早い者勝ちで予約**される
  (`claimWonder`)。他国はもちろん、**自国の別の都市でも**同じ遺産を並行して着工することは
  できない(`canStartProduction`が弾く)。
- 生産を中止すると予約は解放され(`releaseWonder`)、再び誰でも着工できるようになる。
  都市が消滅(食料不足・ミサイル被弾)した場合も同様に自動で解放される。
- Civilization本編のような「建設途中で他国に先を越されたら投資分がゴールドに還元される」
  という競争要素は今回のスコープ外(先に着工した方がそのまま確保する、というシンプルな
  ルール)。
- `/civ:start`(ゲームリセット)で予約状況は全てクリアされる。
- Botは現状、優先度リストに含めていないため自発的には建てない(手動なら人間・Bot問わず
  `cmdStartProduction`経由で建てられる)。

## 9. 施設(facility)

生産キュー(§8)とは別枠の、**即座に設置できる建造物**。`facilities.js` で管理。

- 生産キュー式の建造物との違い:
  - 生産キュー: 都市が生産力を蓄積し、完了まで複数ターンかかる。都市のマスに紐づく。
  - 施設: **労働者の行動回数を1消費するだけで即座に設置**される。都市のマスではなく、
    「自分が領有している空いているマス」(都市も他の施設も無いマス)が対象。
    1つの領地に、空きマスの数だけ複数設置できる。
- データは `tile.facility = { id, label, ownerId, ownerName }` としてマスに直接載る。
- 設置コマンド: `/civ:install <施設ID>`(足元のマスに設置)。メニューからも操作可能。
- 都市(および帰属マス)が占領されると、そのマス上の施設もそのまま新オーナーの資産として
  引き継がれる。

## 10. 区域(district)

都市とは**別の**領有マスに配置する、都市の生産力を使って複数ターンかけて建設する構造物。
`districts.js` で管理。

- 生産キュー式の建造物・施設との違い:
  - 生産キュー式の建造物(§8): 都市**自身のマス**に効果が付き、都市の生産キュー
    (`city.production`)を使う。1都市1つまで同時進行。
  - 施設(§9): 労働者の**行動回数**を1消費して即座に設置される。
  - 区域: 都市とは**別の領有マス**(都市の無いマス)に配置し、その帰属都市の**生産力**を
    使って複数ターンかけて建設される。都市の通常の生産キューとは**別枠**
    (`city.districtConstruction`)で並行して進む。**1都市につき同時に1区域まで**建設できる。
- **区域を建設中のあいだ、その都市は新しい「建造物」を着工できない**(ユニットの生産は
  並行して行える)。
- 建設中に対象マスを失う(占領される等)と、その区域の建設は中止される。
- データは `tile.district = { id, label, ownerId, ownerName }`(完成後)。建設中は
  `tile.underDistrictConstruction = true` が目印として付く。
- 配置コマンド: `/civ:district <区域ID>`(足元のマスで建設開始)。メニューからも操作可能。
- 都市(および帰属マス)が占領されると、完成済みの区域はそのまま新オーナーの資産として
  引き継がれる。
- **区域と施設は同じマスに共存できない**(区域があるマスには施設を置けず、施設があるマスにも
  区域を置けない。互いに排他)。
- **1つの都市につき、同じ種類の区域は1つまでしか配置できない**(`hasCityDistrict()`,
  `districts.js`)。帰属マス(`belongsToCityKey`)を基準に、既に同じ区域IDを保有していないか
  着工前に判定する。すでに保有している場合、メニューの選択肢からもその区域は表示されない。

貯留・消費される。一方、キャンパスの科学力は**都市に留まらず、国家全体の技術ポイント**
(§14の研究)へ直接加算される。具体的には `turns.js` の `processPlayerTurnStart` が、
各都市のキャンパス由来の科学力(flatYields・隣接ボーナス。§6の産出倍率の対象)と、
接続中の交易路の科学力ボーナス(下記)を合計し、人口由来の科学力(人口1につき+1)に上乗せして
`grantProgressPoints` へ渡す。都市の「産出」欄には表示されるが、貯留量(faithStorage の
ような都市ごとの在庫)は持たない。

### 交易路について

`tradingPost`(交易所、上表)が完成すると、`turns.js` の `connectTradeRoutes()` が自動的に、
最も近い都市(所有者は自国・他国どちらでも良い。マス距離が同着なら全て)へ交易路を接続する。
毎ターン(`processPlayerTurnStart`)、接続中の交易路それぞれから以下が両都市の所有者双方に
配られる(§6の産出倍率が自動的に乗る):

- **食料**: 基本+2。接続先も交易所が稼働中なら、距離1で+4、距離2以上なら必要ターン数が半減。
- **ゴールド**: 基本+1。接続先が**他国の都市**なら対外交易として+2(自国内の2倍)。
- **科学力**: 接続先の都市がキャンパス(§10)を持っていれば+1。

交易路には`remainingTurns`(残りターン数、最初の接続時は最短マス距離)があり、毎ターン1ずつ
減っていく。0以下になると、その都市は自動的に`connectTradeRoutes()`を再実行し、最寄りの
都市を再抽選する(周辺の都市構成が変わっていなければ同じ相手と継続、変わっていれば
切り替わる)。接続先の都市が消滅した場合も、この再接続のタイミングで自然に外れる。

## 11. 宗教(religion)

`religion.js` が管理する、信仰力を軸にした宗教システム。1国家につき宗教は1つまで。

### 創始

- 条件: **国家全体(全都市合計)の信仰力が100以上**、かつ**聖地(§10)を1つ以上保有**。
- `/civ:foundreligion` で創始する。100の信仰力は消費されない(閾値の確認のみ)。
- 宗教名は創始時にランダムで決まり、後から `/civ:renamereligion <名前>`
  (またはメニューの[Rename]名前変更)でいつでも変更できる。
- 宗教のIDは、それを創始した国家のIDをそのまま使う(1国家1宗教なので、国家と宗教は1対1)。

### 宗教的圧力・信仰者・主流宗教

- **聖地のある都市**は、自国が宗教を創始していれば、毎ターン自国の宗教の宗教的圧力を
  **+100**する(帰属都市ごと、聖地1つにつき)。
- **伝道者**(下記)が隣接する都市に布教すると、布教した宗教の宗教的圧力が加算される。
  加算量 = 自分の宗教戦闘力 + (自分の宗教戦闘力 × 自分の残りHP%)
  (フルHPの伝道者なら 100 + 100×100% = 200)。
- 都市の各宗教の**信仰者数** = 都市の人口 × (その宗教の圧力 ÷ 都市の累積圧力)。
- ある宗教の信仰者数が**都市の人口の過半数**を超えると、その宗教がその都市の**主流宗教**になる。
- **国家の過半数の都市**が同じ宗教を主流としていれば、それが**国家の主流宗教**になる。
- 都市の上でメインメニューを開くと、その都市の宗教的圧力の内訳(宗教名・国家名・圧力値・割合・
  信仰者数、どれが主流宗教かのマーク)が一覧表示される(§18)。

### 宗教ユニット

社(§10、聖地上)または大聖堂(§10、聖地上)を持つ都市で、都市の**貯留信仰力を使って即座に購入**する
(生産キューは使わない)。`/civ:buyreligious <missionary|apostle|inquisitor>`(またはメニュー)。
購入した都市のマスに配置される。**戦闘ユニットとは別レイヤーで行動する**(`tile.religiousUnit`。
`tile.combatUnit`とは独立)。同じマスに戦闘ユニットと宗教ユニットが同時に存在でき、両者は
通常戦闘しない(戦闘ユニットが宗教ユニットを排除する場合は後述の「異教徒の排除」を使う)。

| ID | 表示名 | 購入条件 | 基本コスト | 宗教戦闘力 | 移動力 | 布教力 | 特記 |
|---|---|---|---|---|---|---|---|
| `missionary` | 伝道者 | 社 | 150 | 100 | 4 | 3 | 布教のみ |
| `apostle` | 使徒 | 大聖堂 | 150 | 110 | 5 | 4 | 布教に加え、敵の宗教ユニットを攻撃可能。審問を開始できる(下記) |
| `inquisitor` | 審問官 | 審問を開始済み(下記) | 130 | 130 | 4 | 3 | 布教は不可。敵の宗教ユニットを攻撃可能。都市の領地内で弾圧が可能。自国領内では宗教戦闘力+10 |

**購入コストの上昇**: 国家が宗教ユニットを1回購入するたびに(種別を問わず共通で)、次回以降の
どの宗教ユニットの購入コストにも**+30**が上乗せされる(`getReligiousUnitCost`。国家ごとの
購入回数を `civ:religiousUnitPurchaseCount` で記録する)。むやみに量産できないようにするための
抑制で、リセットされることはない(試合を通して累積する)。

- **布教**(伝道者・使徒のみ。審問官は不可): 隣接する(距離1の)都市に対して、布教力を1消費
  して行う。**1ターン1回まで**(次の自分のターン開始時にまた布教可能になる)。加算量 =
  自分の宗教戦闘力 + (自分の宗教戦闘力 × 自分の残りHP%)(フルHPの伝道者なら
  100 + 100×100% = 200)。布教力が0になると、その宗教ユニットは自動的に消滅(解散)する。
- **宗教ユニット同士の攻撃**(使徒・審問官のみ): 隣接する(距離1の)敵(同盟関係が無い)の
  宗教ユニットを、**反撃なしの一方的な攻撃**で攻撃できる(**1ターン1回まで**。布教の
  回数制限とは独立してカウントする)。ダメージは通常戦闘(§13)と同じ「24〜36のランダム値 ×
  e^(宗教戦闘力の差×0.04)」の式で算出する。自国の領有マスに立っている側は、宗教戦闘力に
  自国領内ボーナス(現在は審問官のみ+10)が加算された値で計算される。
- **異教徒の排除**: 敵(同盟関係が無い)の宗教ユニットと同じマスに自分の戦闘ユニットがいて、
  かつその戦闘ユニットの移動力が満タン(今ターン未行動)であれば、移動力を全て消費することで、
  戦闘を経ずに無条件でその宗教ユニットを排除できる。

### 宗教ユニットの撃破と圧力スイング

宗教ユニットが撃破されたとき(宗教ユニット同士の攻撃・異教徒の排除のいずれでも共通)、
撃破が起きたマスに**最も近い都市(所有者を問わない)**の宗教的圧力が、撃破した側の宗教
**+1000**、撃破された側の宗教**-1000**(0未満にはならない)だけ変動する
(`applyReligiousKillPressureShift`)。数値が大きいため、この1回の決着だけで都市の主流宗教が
入れ替わることもある(宗教ユニット同士の決着に明確な意味を持たせる狙い)。

### 審問(inquisition)

- 使徒は、**布教力が満タン(=一度もまだ布教していない)** であれば、審問を開始できる
  (一度きりの特殊能力)。開始すると、その国家は以後ずっと審問済み扱いになり(再度の開始は
  不要)、審問官を購入できるようになる。**審問を開始した使徒自身は使命を終えて消滅する。**
- **審問官の弾圧**: 審問官が(所有者を問わず)何らかの都市の領地に属するマスに立っている
  とき、布教力を1消費して、その都市の**自国以外の宗教の圧力を一律80%削減**できる
  (`suppressOtherReligions`)。布教力を使い果たすと解散する(布教と同じ仕組み)。

### 宗教勝利

生存している(都市を1つ以上持つ)全ての国家の**国家主流宗教**が、いずれか1国家の創始した
宗教と一致していれば、その国家の**宗教勝利**(§16)。ソロ勝利の判定の直後、同盟勝利の判定の
前に確認され、参加人数の制限は無い。勝利ポイント+1が付与される。

## 12. 隣接ボーナスシステム

`adjacency.js` が提供する汎用エンジン。**建造物・施設・区域ともに、ルールを1つ追加するだけで
隣接マスに応じたボーナスを持たせられる**(反映側のコードは変更不要)。

```js
adjacencyBonuses: [
    { id: "quarryMountain", label: "山・山脈からの採石恩恵",
      match: matchesTerrainWeighted({ mountain: 1, mountainRange: 2 }), yieldPerMatch: { production: 1 } },
],
```

- `match`: 隣接マス1つがルールに合致するかを判定する関数。ヘルパーが用意されている:
  - `matchesTerrain(...types)` — 指定した地形のいずれか(すべて重み1)
  - `matchesTerrainWeighted({ mountain: 1, mountainRange: 2 })` — 地形タイプごとに異なる重み
    (倍率)を設定できる版。`match` は真偽値の代わりに数値(重み)を返せるようになっており、
    「山脈は山の2倍の恩恵」のような表現に使う(採石場・聖地・工業地帯の山ボーナスで使用)。
  - `matchesResource(...resources)` — 指定した資源のいずれか
  - `matchesBuilding(buildingId)` — 隣が指定の建造物(`city[buildingId]`)を持つ都市マスか
  - `matchesFacility(facilityId)` — 隣が指定の施設(省略時は施設なら何でも)を持つマスか
  - `matchesDistrict(districtId)` — 隣が指定の区域(省略時は区域なら何でも)を持つマスか
  - `matchesAnyCity()` — 隣に何らかの都市があるか
  - 上記で表現できない条件は `match` に直接カスタム関数を書ける。
- `yieldPerMatch`: 条件を満たす隣接マス1つ(重み1)につき加算する量(`food`/`production`/
  `oil`/`faith`/`iron` など任意のキーを使える)。
- `maxMatches`(加算対象にする重みの合計値の上限)、`oncePerTile`(1つでも合致すれば固定量を
  1回だけ加算)もオプションで指定可能。
- 建造物側は `getBuildingAdjacencyYields()`、施設側は `getFacilityAdjacencyYields()`、
  区域側は `getDistrictAdjacencyYields()` が `turns.js` の産出計算(`getCityCurrentYields`)
  から自動的に呼ばれ、都市の産出量に合算される(§6の産出倍率の対象にも含まれる)。人口(労働者配置)
  の影響を受けない、恒久的なボーナス扱い。
- `getAdjacentTiles`/`getAdjacencyBonus` は任意のマス座標に対して使える汎用関数なので、
  区域(都市とは別のマス)のボーナス計算にもそのまま使われている。

## 13. 戦闘

`combat.js` が担当。

- **攻撃・都市の占領には宣戦布告が必要**(§15参照): 戦争状態(`war`)の相手にしか攻撃・占領
  できない。「関係なし」はもちろん、不可侵条約・同盟の相手も対象外。
- **他国の領土への移動制限**(§15参照): 「関係なし」の相手が所有するマスには進入できない。
  宣戦布告した相手・不可侵条約・同盟の相手の領土になら進入できる。
- **近接 / 遠距離の区別**: `rangedCombatStrength` を明示的に持つユニットは常に遠距離ユニット。
  持たない場合でも `attackRange > 2` なら遠距離ユニットとみなす。
- **兵種(unitClass)とクラス相性ボーナス**: 各ユニットは `unitClass` を持ち、特定の兵種同士の
  組み合わせでは戦闘力にボーナスが付く(Civilization VIのユニットクラス相性を参考にした
  「対騎兵は騎兵に強い」のようなじゃんけん関係。`UNIT_CLASS_COUNTERS`)。

  | 兵種 | 該当ユニット | 特記 |
  |---|---|---|
  | `melee`(近接) | 戦士・剣士・銃士・近代歩兵 | 標準的な前線ユニット(銃士・近代歩兵も、現実の間合いではなく「主力歩兵」という役割上melee扱い)。**対騎兵(antiCavalry)クラス相手に戦闘力+5** |
  | `antiCavalry`(対騎兵) | 槍兵・長槍兵 | **騎兵(cavalry)クラス相手に戦闘力+10**。近代以降は上位互換を持たない(騎兵側が戦車へ進化して以降、対騎兵という役割自体が下火になるため) |
  | `cavalry`(騎兵) | 騎兵・騎士・戦車 | 移動力が高い機動戦力。対騎兵には弱い。戦車は騎兵・騎士の系譜の最終形態(兵種はcavalryのまま) |
  | `ranged`(遠隔) | 弓兵・重装弓兵・機関銃兵 | 2マスの遠距離攻撃 |
  | `siege`(攻城) | カタパルト・大砲・近代砲兵 | 遠距離戦闘力は最大級だが近接戦闘力(防御時)は低い。都市の防壁を無視する(下記) |
  | `naval`(海軍) | 帆船・巡洋艦・戦艦 | 水上マス専用 |

  `melee`/`antiCavalry`/`cavalry`の3クラスは、都市戦闘力の算出・都市からの反撃可否・防壁の
  被ダメージ軽減率のいずれにおいても「近接系」としてまとめて扱われる(`isMeleeUnitClass`、下記)。

  ボーナスは攻撃側・防御側という役割ではなく「そのユニット自身」に乗るため、対騎兵ユニットが
  騎兵を攻撃する場合も、逆に騎兵に攻撃された場合(防御・反撃のいずれも)も等しく+10される
  (`getClassMatchupBonus`、`resolveCombat`/`canGuaranteeKill`の両方に組み込み)。新しい
  クラス相性を追加したい場合は `combat.js` の `UNIT_CLASS_COUNTERS` に1行足すだけでよく、
  反映側のコード変更は不要(adjacency.js の隣接ボーナスと同じ設計思想)。兵種は生産メニュー・
  攻撃対象一覧・アクションバー・マス上のユニットラベルのいずれにも表示される。
- **戦闘力の選び方**:
  - 先制攻撃(攻撃側): 遠距離ユニットなら遠距離戦闘力、そうでなければ近接戦闘力を使用。
  - 反撃(防御側): 攻守が隣接していない(距離2以上)なら防御側の遠距離戦闘力を使用。
    隣接している場合、攻撃側が近接ユニットなら防御側の近接戦闘力、攻撃側が遠距離ユニット
    なら防御側の遠距離戦闘力を使ってよい。
  - 防御力(ダメージを受ける側の抵抗力)は、先制・反撃どちらでも常に近接戦闘力を使う
    (遠距離戦闘力は「撃つ側」専用)。
- **反撃を受けない条件**: 攻撃側が防御側の攻撃範囲外から攻撃した場合、反撃は発生しない。
- **包囲ボーナス(flanking)**: 攻撃対象に隣接する8マスのうち、攻撃側自身のマスを除いて
  自軍の戦闘ユニットが存在するマスの数(`countFlankingAllies`)に応じて、攻撃側の
  先制攻撃力にボーナスが付く(1体につき+3、最大4体分=+12まで、`getFlankingBonus`)。
  複数のユニットで敵を取り囲んでから攻撃すると有利になる。反撃側の戦闘力には影響しない。
  戦闘メッセージに包囲ボーナスが発生した場合はその内訳が表示される。
- **ダメージ計算**: `(24〜36のランダム値) × e^(戦闘力の差 × 0.04)`。小数点以下切り捨て
  (戦闘力の差には上記の包囲ボーナスも含む)。
- ダメージを受けたユニットは戦闘力が低下する(現在HPベースの派生値。HPが10減るごとに-1、
  最大-9。基礎値そのものは変化しない)。
- **HPが0以下になったユニットは撃破される**。
- 戦闘勝利では勝利ポイントは付与されない(§16参照。付与はゲーム勝利時のみ)。
- **回復(休息)**: 今ターンまだ一度も行動していない(移動力が最大値のまま)戦闘ユニットは、
  行動力を全て消費してその場で休息し、最大HPの30%分HPを回復できる
  (`cmdHealCombatUnit`, `commands.js`)。既に移動・攻撃・占領などで行動済みのユニットや、
  HPが既に満タンのユニットは使えない。メニューでは、対象ユニットのマスに立っているときに
  「このユニットを休息させて回復する」ボタンとして表示される。
- **移動の地形制約**: 陸軍ユニットは陸地マスのみ、海軍ユニットは水上マス(海・川・池・湖)のみに
  移動できる(`canUnitEnterTerrain`)。山脈マスにはどちらも進入できない(§2)。
  `canUnitEnterTile` は、この地形適性と他国領土への進入可否(`canUnitEnterOwnership`、
  §15)の両方を満たすかどうかを総合判定する。
- **移動経路の検証(経路探索)**: 戦闘ユニットの移動先は、8方向(縦・横・斜め)への1マス移動を
  移動力1として消費する幅優先探索(`combat.js`の`getReachablePositions`)で、今の残り移動力の
  範囲内で実際に経路がつながる全マスとして求める。斜め移動も縦横移動と同じ移動力1で済むため、
  障害物が無ければ最短到達コストは常に方眼距離(chebyshev距離: `max(|dx|,|dz|)`)と一致するが、
  地形(海軍ユニットにとっての陸地など)・他国の「関係なし」領土・他ユニットなどの障害物を
  迂回する必要がある場合は、その分実際の消費移動力が増える(それでも今の残り移動力の範囲内
  なら移動できる)。通過点(最終着地マス以外)は他ユニットが乗っていないマスである必要があり、
  そこで探索が打ち切られる(他ユニットを飛び越えることはできない)。UIの移動先一覧にも
  反映され、実際に移動できないマスは候補にすら表示されない(以前は8方向の直進上のマスにしか
  移動できなかったが、迂回を挟んだ曲がった経路でも移動力が足りれば到達できるよう変更した)。
- **マス上のユニット表示**: `unitLabels.js` が、実験的API `TextPrimitive` を使って
  戦闘ユニット(兵科・名前・所有者・HP)/宗教ユニット(名前・所有者・HP、`[Faith]`タグ)の
  いるマスの上にラベルをワールド内に常時表示する(約1秒間隔で同期)。**戦闘ユニットと
  宗教ユニットは同じマスに重なりうる**(§11/§13参照)ため、その場合は1つのラベルに
  両方の内容を連結して表示する(マスごとに1つの`TextPrimitive`しか対応させない設計)。
  `TextPrimitive` はワールドの「ベータAPI」実験的機能が無効だと使えないが、その場合は
  例外を捕まえて機能全体を静かに無効化するだけで、他の機能には影響しない。ユニットが
  撃破/消滅した瞬間、およびゲームの終了/リセット時にはラベルも即座に消去(または、
  重なっていたもう一方のユニットだけの内容に更新)される。
- **マス上のユニットの3Dモデル表示**: `unitModels.js` が、見た目モデルが用意されている
  ユニット(現状は`tank`(戦車)・`warrior`(戦士)のみ)について、実際のエンティティ(`civ:tank`・
  `civ:warrior`、リソースパック「testapia_models」側で定義)をそのユニットが乗っているマスの
  上に配置する。仕組みは
  `unitLabels.js`と同じ(`getStateVersion()`で変化を検知、約1秒間隔で間引き同期、マス単位で
  現在の配置物を管理)で、production.js・turns.js・ui.js側に個別のフックを追加していない。
  ユニットが撃破された場合の反映は次回の定期同期(最大1秒弱)を待つ。移動は下記の
  「ユニット移動のアニメーション」を参照(こちらは`commands.js`から直接呼ばれる別経路)。
  戦車以外のユニットは`unitModels.js`の
  `MODEL_TYPE_IDS`に追加すれば同じ仕組みで表示できる。配置するY座標は`config.ySurface + 1`
  固定ではなく、そのマスの実際の地表(山タイルの隆起分など)を最大4ブロック分探索して
  求める(`findGroundY`。山脈(mountainRange)はimpassableでユニットが乗ることは無いため
  考慮不要)ため、山タイルに乗った戦車が地形に埋まることはない。森林/熱帯雨林タイルは
  `mapGen.js`がタイル中心に木を生やす(葉は幹の周囲1マスに展開)ため、この地形のときだけ
  タイル中心ではなく葉の範囲外(端寄り)に配置し、木と重ならないようにしている。戦車の形状は車体+キャタピラ
  (左右各4個のロードホイール付き)+砲塔+砲身の計13キューブ(2ボーン: `body`/`turret`)。
  テクスチャは64x96の3色プレースホルダー(車体:オリーブグリーン、砲塔・砲身:やや暗い
  オリーブグリーン、キャタピラ・ロードホイール:チャコール。面積の大部分を占める車体は
  緑のまま、キャタピラだけ非緑にして各パーツの見分けをつきやすくした)で、ドット絵の
  描き込みはまだ無い。`testapia_models`はワールド設定でリソースパックとして手動有効化する
  必要がある。
- **ユニット移動のアニメーション**: `commands.js`の`cmdMoveCombatUnit`(戦闘ユニットの移動)が、
  移動データの更新・ブロードキャストの直後に`unitModels.js`の`animateUnitModelMove()`を呼ぶ。
  見た目モデルのあるユニット(現状は戦車)が、瞬間移動ではなく目的地へ直進するアニメーションで
  移動する。移動経路の途中は数tickごとに`findGroundY`を呼び直してYを求め直すため、山の斜面
  などの高低差にも追従する。移動方向(dx, dz)からyawを算出し(`yawTowards`)、アニメーション中
  ずっとその向きを保つ(=目的地の方を向いて直進する)。**人間プレイヤーの操作時のみ**このアニメーションを待ってから
  コマンドが完了する(アニメーション中は次のメニュー操作に進めない)。Bot(自動操作国家)は
  1ターンで複数ユニットを連続移動させるため体感速度を落とさないよう対象外とし、
  `makeBotIdentity`(bots.js)が返すBot用の疑似プレイヤーオブジェクトに立てる`isBot`フラグで
  判別している(Botの移動はこれまで通り即時反映)。見た目モデルの無いユニットの移動は
  今まで通り即時完了する(`animateUnitModelMove`が対象マスにモデルを見つけられなければ
  何もせず即座に解決するため)。

### 都市(都心)の攻防

都市自身のマス(「都心」)は、通常の戦闘ユニットとは別に**独自のHP・戦闘力を持つ防衛拠点**
として機能する(Civilization VIの都市戦闘を参考にした仕組み)。首都・都市を問わず、建設時に
自動でこの状態になり、プレイヤーが個別に配置・解除することはできない。

- **都心のHP**: 200(`CITY_MAX_HP`)。**このHPが0を超えている間、敵(自国でも同盟・不可侵
  条約の相手でもない)ユニットはそのマスへ進入できない**(`canUnitEnterCityTile`。移動・
  経路上の通過点いずれにも適用される)。占領するには、まずこのHPを0まで削り切る必要がある。
- **回復**: 毎ターン、都市所有者の手番開始時に+30回復する(`CITY_HP_REGEN_PER_TURN`)。ただし
  隣接する8マスに戦争状態の敵の戦闘ユニットが1体でもいる(=「包囲」されている)ターンは
  回復しない(`isCityBesieged`)。
- **都市戦闘力**: `max(自国最強の近接系ユニットの戦闘力 - 10, 都市に駐留中のユニットの実効
  戦闘力)` で算出する(`getCityCombatStrength`)。近接系ユニット(`melee`/`antiCavalry`/
  `cavalry`)から攻撃された場合、都市はこの戦闘力で**反撃**する(ダメージ計算は通常の戦闘と
  同じ式)。遠距離・攻城ユニットからの攻撃には反撃しない。都市に駐留するユニット自体は、
  `cmdAttackCombatUnit`(通常のユニット同士の攻撃)からの**直接の攻撃対象にはならない**
  (garrison化)が、下記の通り都市への攻撃でHPが並列に削られるため、放置していれば都心が
  陥落するより先に駐留ユニット単体が力尽きることもある。
- **都市への攻撃**: 攻撃距離内の敵都市は、駐留ユニットの有無に関わらず攻撃対象になる
  (`getAttackableCityTargets`。メニューの「ユニットの攻撃」に統合表示され、通常の敵ユニットと
  同じ一覧から選べる)。ダメージ計算・防壁の軽減などは下記。攻撃すると、そのユニットは
  戦闘ユニット同士の攻撃と同様に今ターンの残り移動力を使い切る。防壁を抜けて都心HPに届いた分
  のダメージ(`hpDamage`)は、駐留ユニットがいる場合そのHPにも**同じ量だけ並列で**適用される
  (`resolveCityAttack`)。都心・駐留ユニットのどちらが先に力尽きるかは互いに独立で、駐留
  ユニットのHPが0になれば都市が陥落していなくても駐留ユニットだけ即座に撃破される(空になった
  都市はまだ占領できない。占領には引き続き都心のHPを0にする必要がある)。防壁は都心・駐留
  ユニットの両方を一緒に守る(軽減後のダメージが両者に共通で入る)。

#### 防壁(`wall`、技術「石工術」で解放)

| 効果 | 内容 |
|---|---|
| シールドHP | +100(`WALL_MAX_HP`)。都心のHPとは別枠で先に削られる「盾」として機能する |
| 遠距離攻撃 | 都市自身が範囲3(`CITY_RANGED_ATTACK_RANGE`)の敵ユニットを攻撃できるようになる。戦闘力は自国最強の遠距離ユニットの遠距離戦闘力と同じ(`getBestRangedCombatStrength`)。反撃は発生しない。1都市1ターン1回まで |
| 被ダメージ軽減 | 攻撃側の兵種に応じてダメージが軽減される(`getWallDamageMultiplier`): 近接系(`melee`/`antiCavalry`/`cavalry`)は**15%**、遠隔(`ranged`)は**50%**、**攻城(`siege`)は軽減されない(100%)** ── 攻城ユニットは防壁をすり抜ける設計 |
| 修理 | 都市が直近のターンで攻撃を受けていない(`city.attackedRecently`が false)場合のみ、労働者の行動回数を1消費してシールドHPを満タンまで修理できる(`cmdRepairWall`) |

防壁が無い都市は、ダメージがそのまま都心のHPに直接入る(軽減もシールドも無し)。防壁がある
場合、ダメージはまずシールドHP(`city.wallHp`)から削られ、削りきれなかった分だけ都心のHPに
入る。都心のHPが0になった時点でシールドの有無に関わらず陥落状態になる。

占領(`cmdCaptureCity`、§5)に必要な「都市のマスに自分のユニットが移動力満タンで立っている」
という条件自体は変わらないが、都心のHPが0を超えている間はそもそもそのマスへ移動できないため、
実質的な流れは「攻撃で都心のHPを0まで削る → 空いたそのマスへ移動する → 次の自分のターンで
占領する」という2段階になる。占領が成立すると、都心のHP・シールドは満タンに戻る(防壁自体は
破壊されず、他の建造物と同じく占領側の資産として引き継がれる)。

都心のHPが0になった時点で、そのマスに駐留ユニット(garrison)が残っていても進入・移動できる
(`combat.js`の`isFallenEnemyCityTile`。戦争相手かつHP<=0の場合のみtrue)。移動すると駐留
ユニットは都心と共に敗北した扱いで取り除かれ、移動してきたユニットがそのマスに立つ
(移動先候補の一覧(UI)・Botの移動先探索のいずれも、この場合だけ「マスが占有されている」
判定を素通りする。ただし経路の**途中**に他の占有マスがある場合は、陥落した都市かどうかに
関わらず今まで通り通過できない)。同盟・不可侵条約の相手の**健在な**都市(HPが残っている)
には、この「陥落」判定は成立しない(`isAtWar`で戦争相手かどうかを厳密に見ているため、味方の
駐留ユニットが誤って除去されることはない)。

(カタパルト→近代砲兵・戦車・戦艦→機関銃兵・近代歩兵→ミサイル・対空砲と繋がる、このツリー

### 偉人(新要素)

`progression.js`が管理する、技術/文化力/信仰力の産出の一部から貯まる「偉人ポイント」
(`科学`/`文化`/`信仰`の3種別、国家単位のDynamic Property`civ:greatPersonPoints`)。

- 毎ターン、その国家が獲得した技術ポイント・社会制度ポイント・信仰力のそれぞれ**20%**
  (`GREAT_PERSON_POINT_SHARE`)が、対応する種別の偉人ポイントに追加で加算される
  (通常の技術/社会制度/信仰力の蓄積を消費するわけではなく、横から追加で貯まる)。
- いずれかの種別が**150ポイント**(`GREAT_PERSON_THRESHOLD`)に達すると、メインメニューに
  「[Great] 偉人を招聘する」ボタンが表示される(未達の種別はボタン自体が出ない)。
- 招聘すると、その種別のポイントを使い切り、即時ボーナスを得る(`cmdRecruitGreatPerson`):
  - **大科学者**(科学): 技術ポイント+250を即座に付与。
  - **大文人**(文化): 社会制度ポイント+250を即座に付与。
  - **大預言者**(信仰): 自国の全都市の信仰力備蓄(`faithStorage`)に、都市ごとに+50を加算。
- `/civ:start`で偉人ポイントは全てリセットされる。

### 天災(新要素)

`turns.js`の`applyClimateDisasters`が、既存のCO2蓄積(§24)を利用した天災イベントを扱う。
自国のCO2蓄積量(`strategic_co2`)が**150**(`CLIMATE_DISASTER_CO2_THRESHOLD`)を超えている
場合のみ対象になり(CO2を出していない国家には一切影響しない)、超過分50ごとに発生率+5%
(最大30%、`CLIMATE_DISASTER_CHANCE_CAP`)で毎ターン抽選される。発生すると、自国の都市から
ランダムに1つ選ばれ「干ばつ」が起き、蓄積食料(`foodStorage`)を最大75(`CLIMATE_DISASTER_
FOOD_LOSS`)失う(0未満にはならない)。原子力事故(§24)と違い都心HP・人口・建造物には
影響しない、比較的軽い一回性のイベント。

## 15. 外交

`diplomacy.js` が管理する2国間の関係は次の4種類。

| 関係 | 内部値 | 成立方法 |
|---|---|---|
| 関係なし | `none` | 初期状態、または戦争状態からの講和(提案→承認)後 |
| 不可侵条約 | `pact` | 提案(社会制度「使節団」が必要)→ 相手が承認 |
| 同盟 | `alliance` | 提案(社会制度「外交」が必要)→ 相手が承認。不可侵条約からの格上げも可 |
| 戦争 | `war` | **宣戦布告**(declareWar)。一方的に成立し、相手の承諾は不要 |

- 外交メニューは**ゲーム中ならいつでも**開けるが、対象は**実際にゲームに参加済み
  (`/civ:join`済み)の国家のみ**(ワールドに入っているだけの未参加プレイヤーは対象外)。
- 不可侵条約/同盟/講和はいずれも「提案(`sendRequest`) → 相手が承認(`acceptRequest`)/
  拒否(`rejectRequest`)」という同じ申請の仕組みを使う(相手に届いた提案は外交メニューの
  「届いた外交提案」から確認できる)。不可侵条約/同盟の提案には社会制度(使節団/外交)の
  取得が必要(提案する側にのみ要求。承認する側には要求しない。講和にcivic条件は無い)。
  **戦争状態の相手には不可侵条約・同盟を提案できない**(先に講和が必要)。逆に講和は
  **戦争状態の相手にしか提案できない**。
- 不可侵条約/同盟を結んでいる相手には、攻撃できない・国境ペナルティ住宅-1が適用されない。
- 相手国詳細画面には関係の種類・戦争中かどうかを問わず常に「[Gold] ゴールドを贈る」ボタンが
  あり、相手の承諾を必要としない一方的なゴールドの贈与ができる(§23)。

### 宣戦布告(declareWar)と戦争(war)

- 外交メニューの相手国詳細画面から「§4[War] 宣戦布告する」でいつでも宣戦布告できる
  (確認ダイアログあり)。相手の承諾は不要で、選択した瞬間に双方が戦争状態になる。
  既に結んでいた不可侵条約・同盟があれば同時に破棄される(=同盟や不可侵条約を破っての
  開戦も可能)。
- **戦闘ユニットの攻撃・都市の占領は、戦争状態の相手にしか行えない**(`commands.js` の
  `cmdAttackCombatUnit`/`cmdCaptureCity` が `isAtWar()` で判定する)。「関係なし」は
  もちろん、不可侵条約・同盟の相手にも(破棄せずに直接)攻撃・占領はできない。
- **「関係なし」の相手が所有するマスには、戦闘ユニットが進入できない**(`combat.js` の
  `canUnitEnterTile`)。宣戦布告した相手(war)・不可侵条約(pact)・同盟(alliance)の
  領土になら進入できる(同盟・不可侵条約の相手の領土を平和的に通過するのは可能。ただし
  上記の通り、そこにいる相手ユニット・都市を攻撃・占領するには別途宣戦布告が必要)。
  宗教ユニット(伝道者)の移動はこの制限の対象外(布教という性質上、他国の領土への進入が
  前提のため)。
- **講和**: 戦争状態の解消は、不可侵条約・同盟の解消(`breakRelation`、一方的に即成立)とは
  異なり、外交メニューから「講和を提案する」→ 相手が承認して初めて成立する
  (`sendRequest`(type: `"peace"`)/`acceptRequest`)。送った側が一方的に即講和できてしまうと
  都合が良すぎるための仕様。相手が拒否する、または放置することもできる。
  **試合の設定で講和が無効化されている場合は、提案の送信・承認どちらも拒否される**(下記参照)。
- 戦争中は §13 の「関係なしのときの脅威判定」は適用されず、通常の警戒距離(6マス)で
  脅威を判定する(下記参照)。

### 試合の設定による無効化

- **試合の設定でOPが「不可侵条約・同盟」自体を無効化できる**(§18のメニュー、既定は有効)。
  無効化すると、civic条件を満たしていても新規の提案送信・提案の承認ができなくなる
  (`diplomacy.js` の `sendRequest`/`acceptRequest` が拒否する)。既に成立している関係は
  無効化しても自動では解消されない(破棄したい場合は通常どおり手動で破棄する)。
  **この設定は宣戦布告には影響しない**(宣戦布告は不可侵条約・同盟とは独立した機能で、
  試合の設定を問わず常に行える)。
- **試合の設定でOPが「講和」自体を無効化できる**(§18のメニュー、既定は有効)。
  無効化すると、戦争状態(war)を終了させる講和の提案・承認自体ができなくなる
  (`sendRequest`/`acceptRequest`が type: `"peace"` に対して拒否メッセージを返す)。
  **不可侵条約・同盟の解消(破棄、`breakRelation`)にはこの設定は影響しない**(常に可能)。
  一度始まった戦争を終わらせられなくする、いわゆる「殲滅戦」ルール用の設定。
  無効化中は、Bot側の劣勢時の自動講和提案(§3-1)も行われなくなる(宣戦布告自体は影響を受けない)。

## 16. 勝利条件と勝利ポイント

`turns.js` の `checkAndAnnounceVictory()` が、都市占領時・ミサイル着弾時・ターン開始処理の
直後に判定する。

- **ソロ勝利**: 生存国家(都市を1つ以上持つ国家)が1つだけになったら、その国家の勝利。
  - 参加国家が最初から1つ(ソロテスト等)の場合は判定しない。
  - まだ一度も首都を設置していない(参入準備中の)国家が残っている間は判定を見送る
    (誤って「脱落」と判定しないため)。
- **宗教勝利**(§11参照): 生存している全ての国家の国家主流宗教が、いずれか1国家の創始した
  宗教と一致していれば、その国家の勝利。ソロ勝利の直後・同盟勝利の前に判定され、
  参加人数の制限は無い。
- **同盟勝利**: 生存国家が2つ以上でも、**そのゲームの参加人数が4人以上**の場合に限り、
  生存者全員が互いに同盟関係にあれば、その同盟グループ全体の勝利になる。
- 勝利が確定すると、結果がワールドにブロードキャストされ、ゲームがリセットされる
  (研究・外交・首都フラグ等がクリアされ、次回 `/civ:join` からやり直しになる)。
- **勝利ポイント**(`civ:victoryPoints`): ゲームに勝利した国家(同盟勝利なら全員)に+1付与。
  戦闘の勝敗では付与されない。**他ゲームでいうレート的な値**として、`/civ:start` の
  リセット対象には含まれず、ゲームをまたいで持続する。メインメニューに表示される。
- **【デバッグ】OPによる即座の勝利**: 通常の勝利条件を一切判定せず、OPがメニューから選んだ国家
  (1つなら単独勝利、複数選べば同盟勝利)を即座に勝利させる機能がある(`debugForceVictory`,
  turns.js)。勝利ポイント付与・ブロードキャスト・ゲームリセットは通常の勝利と同じ処理を行う。
  動作確認・デモ用のショートカットで、メインメニュー(ゲーム進行中・OPのみ)から利用できる。

## 17. ミサイル

- 都市の生産で作成(cost 200、前提技術「ロケット工学」§14)。都市ごとに在庫として蓄積される。
- 自分の都市から、マップ内の任意のマス座標へ発射できる(`/civ:launch <x> <z>`)。射程距離の
  制限は無い。
- **1都市につき1ターンに1発まで**(`city.missileLaunchedThisTurn`。その都市の手番が
  回ってくるたびにリセットされる)。
- **着弾地点に他国の都市がある場合、宣戦布告済み(戦争状態)の相手にしか発射できない**
  (§13・§15の攻撃・都市占領と同じ制約)。無所属マス・空きマスへの発射は制限しない。
- **対空砲(`antiAir`、建造物、cost 200、前提技術「ロケット工学」、§8)による迎撃**: 着弾地点(自身を含む)からマス距離
  1以内(=着弾地点と周囲8マス)に、その時点でまだ今ターンの迎撃を使っていない対空砲を持つ
  都市が1つでもあれば、着弾前に撃墜される。撃墜されたミサイルは着弾せず、爆発・都市破壊など
  一切の効果が発生しない。対空砲側も1都市につき1ターンに1回まで(`city.antiAirUsedThisTurn`。
  その都市の手番が回ってくるたびにリセットされる)。迎撃は所有者・外交関係を問わず、
  範囲内に使用可能な対空砲があれば発動する。
- 迎撃されなかった場合、発射から2秒後に着弾。着弾地点に都市があれば、そこは即座に完全に
  破壊(消滅)する。
- 着弾直後にも勝利条件の判定が行われる。

**対空砲は空軍ユニット(§25)の出撃(攻撃・略奪)も同じ仕組みで迎撃する**
(`turns.js`の`findInterceptingAntiAirCity`をミサイル・空軍の両方で共用)。空軍ユニットが
他ユニット/都市を攻撃・略奪する際、攻撃先マスの周囲1マス以内に未使用の敵対空砲があれば、通常の
戦闘解決の前に出撃側の空軍ユニットが撃墜され、消滅する(反撃・ダメージ計算は一切発生しない)。
移設(§25の「移設」。空軍ユニットの拠点間移動)だけを行う空軍ユニットは対空砲の対象にならない。
対空砲の使用回数(1都市1ターン1回)はミサイル迎撃と共有する。対空砲が範囲内に無い場合、
哨戒中の空軍ユニット(§25)による2段目の迎撃が試みられる(確実な撃墜ではなく、ダメージを
与えるのみ)。

## 18. UIメニュー構成

コンパスを使用、または `/civ:menu` でメインメニューを開く。

- **アクションバーHUD**(`main.js`、0.5秒ごとに更新): 足元のマスの座標・地形・資源・領有・
  都市/施設/区域・戦闘ユニット/宗教ユニットに加えて、今操作している国家の保有ゴールド
  (§23、残高がマイナスなら破産中の警告付き)を常に表示する。都市の上にいて自国・同盟国の
  都市の場合は、その都市の今の産出量・生産中の物などに加えて、受電量が1以上か工場を持つ
  都市に限り電力の受給量(§24)も表示される。
- **表示スタイルの切り替え(「§b[UI] チェストUIに切り替える」/「§b[UI] 通常のメニューに
  切り替える」)**: メインメニューは、通常のフォーム(`ActionFormData`)と、チェストの
  アイテムを選ぶような見た目の「チェストUI」を、いつでも切り替えられる。切り替えは
  プレイヤー個人の表示設定であり(`player`のDynamic Property `civ:menuStyle` に保存、
  ゲームリセットを跨いでも保持される)、試合の設定とは独立している。
  - **チェストUIを使うには、このBPと対になる補助リソースパック
    `development_resource_packs/testapia_ui` を、ワールド側で(BPと同様に)有効化する
    必要がある**。有効化していない状態でチェストUIに切り替えると、内部的な目印文字列が
    そのまま見えてしまう崩れた見た目のフォームが表示される(動作自体は壊れない。困ったら
    もう一度切り替えボタンを押せば通常表示に戻せる)。
  - 実装は `ui.js` の `ChestFormData`(`chestForms.js`)経由。ActionFormDataのタイトル文字列に
    特殊なマーカーを仕込むことで、リソースパック側の `ui/server_form.json` がそれを検知し、
    チェスト風パネル(`ui/chest_server_form.json`)へ差し替える仕組み(通常のフォームの
    描画経路自体には一切手を加えていないため、マーカーの付かない他の全てのActionFormData/
    ModalFormDataは今まで通り表示される)。チェストUIには通常のフォームにあるような本文欄が
    無いため、ターン情報などは最後の1マスに「現在の状況」枠(説明文がアイテムの説明欄に載る)
    として表示する。スライダー・トグル・テキスト入力を伴う画面(試合の設定・マップ生成の設定・
    都市名変更など、`ModalFormData`を使う画面)はチェストUIでは再現できないため、選んだ
    スタイルに関わらず常に通常のフォームで表示される。
  - `development_resource_packs/testapia_ui` は [Chest-UI](https://github.com/Herobrine643928/Chest-UI)
    (Herobrine64#3928, LeGend077 作、CC BY 4.0)のUI定義・テクスチャを一部改変して同梱している
    (詳細は同パック内の `CREDITS.md` を参照)。
- **OP専用(テスト機能): 「§b[Test] マップを見る(チェストUI)」**(マップ生成済みの時のみ表示):
  マップ全体をチェストUI(`ui.js` の `openMapViewMenu`)で一覧できるビューア。マップ全体は
  54マスのチェストに収まりきらないことが多いため、一度に9×5マス(45マス)分だけを表示し、
  下段1行(9マス)を上下左右の移動・現在地表示・閉じる専用に固定する。ボタンを押すごとに
  表示範囲が1画面分(横9マス/縦5マス)動く。各マスのアイコンは、都市なら所有者の色の旗、
  所有マスなら所有者の色の羊毛(誰の領土かが色で一目でわかる、Risk風の見た目)、それ以外は
  地形(バイオーム)そのもののアイコン、という優先順位で選ばれる(資源・ユニットの有無では
  アイコンを変えない。バイオーム/所有者の色分けの見分けやすさを優先している)。カーソルを
  合わせると、座標・地形・基礎産出量(foodYield/productionYield)・資源(あれば)・
  所有者(いれば)・**戦闘ユニット/宗教ユニットの有無(いれば所有者・種類・HP)**を説明欄で
  確認できる。
  グリッド状の情報は通常のフォームでは表現しづらいため、通常フォーム版は無く常にチェストUIとして開く
  (§18の表示スタイル設定とは独立)。そのため、補助リソースパックが無効な状態で開くと
  崩れた見た目になる(壊れはしない)。
- **「§b[Help] ルール説明を見る」**: ゲーム開始前・進行中を問わずいつでも開ける簡易ルール説明
  (`ui.js` の `HELP_TOPICS`)。「基本の流れ」「生産と経済」「戦闘」「航空戦」「外交」「勝利条件」の
  6項目に分かれており、それぞれ数行の要約を読める(README.mdの全項目ではなく要点のみ)。
  項目一覧・詳細画面ともに「戻る」でメインメニューまで戻れる。
- 上部の情報欄: 現在地の地形・資源・所有者・**このマスの戦闘ユニット情報・施設情報**、
  保有石油・保有鉄・保有馬・保有ゴールド(残高がマイナスなら破産中の警告付き。§23)・
  保有石炭・保有ウラン(§24)、
  **勝利ポイント**、待機中/操作中プレイヤー一覧など。
  都市の上にいる時はさらに、その都市の**宗教的圧力の内訳**(§11)、および受電量が1以上か
  工場を持つ都市に限り**電力の受給量と発電所ごとの内訳**(§24)も表示される。
- **他国の都市の詳細情報は非表示**: 自国・同盟国以外(戦争中・不可侵条約・関係なしを問わず)
  が所有する都市の上にいる/隣接マスから帰属している場合、人口・住宅上限・労働者数・現在の
  産出量・生産中の物と進捗・区域建設の進捗・交易所の稼働状況と交易路・貯留食料/信仰力・
  宗教的圧力の内訳・飢餓ターン数・保有ミサイル数といった内部管理情報は一切表示されない
  (アクションバー・メインメニューの両方。都市の存在・所有者名・都市名までは見える)。
  相手の都市を物理的に偵察して有利な情報を得られてしまうのを防ぐための制限
  (`main.js`/`ui.js` の `isFriendlyOwner`/`isFriendlyCity` 判定。OP専用の
  デバッグメニュー「全国家の情報を閲覧する」はこの制限の対象外)。
  **この試合に参加していない(`turn.playerOrder`に含まれない)純粋な観戦者には、
  この制限自体を適用しない**(誰の都市の上に乗っても詳細情報が見える)。偵察が有利不利に
  繋がるのは対戦している当事者間だけなので、観戦者(あるいは操作中の国家が未参加の状態の
  プレイヤー)には制限をかける理由が無いための挙動。
- ゲーム開始前: 参加ボタン。OPのみ「全プレイヤーを参加待機状態にする」ボタン(下記参照)。
- 都市の上にいる時: 都市名変更・生産メニュー・ミサイル発射(在庫があれば)。生産中なら
  「[Gold] ゴールドで即時完成」ボタンも表示される(必要ゴールド額つき。§23)。
- 森林/熱帯雨林(未伐採)の上: 伐採ボタン。
- 空いている領有マスの上: 施設を設置するボタン、区域を配置するボタン。
- 自分の戦闘ユニットがいるマス: 移動・攻撃ボタン、(都市なら)占領ボタン。
  - ユニット移動メニューには、通常の全マス一覧に加えて「今いる場所へ移動」ボタンがある
    (プレイヤーが実際に歩いて目的地まで移動してからメニューを開くと、その座標への移動が
    一覧の先頭にワンタップで表示される)。
- ゲーム開始後: 外交メニュー、**自分の戦闘ユニット一覧**(マップ上どこからでも移動・攻撃可能)、
  **航空部隊一覧**(§25。全都市の航空基地に配置中のユニットをまとめて操作可能)。
- OPのみ: ゲームリセット、手番の強制スキップ、国家管理(テスト国家の追加/切替、**Botの追加**、
  **テスト国家/Botの削除**)。削除画面はトグルの一覧になっており、**複数選んで一括削除できる**
  (全部消したい場合は全トグルをONにすればよい)。削除はゲーム開始後はできない(所有マス・
  都市などゲーム内状態に取り残しが発生するのを防ぐため、追加時と同じ制約)。取り消せない
  操作のため確認ダイアログを挟む。
- **OP専用: 試合の設定**(「§e[Settings] 試合の設定」): 以下の5項目を変更できる。
  - 産出の倍率(スライダー、1〜10段階=x0.5〜x5を0.5刻みで指定。小数を直接スライダーに渡すと
    環境によって不具合が出たため、整数段階のスライダーを内部でx0.5倍する方式にしている)。
  - 不可侵条約・同盟の有無(トグル)。
  - 講和の有無(トグル、§15参照。無効にすると一度始まった戦争を講和の提案・承認で
    終了できなくなる、いわゆる「殲滅戦」ルール)。
  - Botの手番間隔(スライダー、1〜100tick。Bot同士の対戦を見やすくする速度調整、§3-1参照)。
  - **行動ログの表示(トグル)**: 無効にすると、領有・都市建設・生産・戦闘・外交など
    ほぼ全ての行動ログ(`world.sendMessage`による全員への通知)が表示されなくなる
    (`state.js`の`broadcast()`が、この設定を見て`world.sendMessage()`の呼び出し自体を
    省略する)。**領有・都市建設・伐採・ミサイル発射に伴うタイトル演出/効果音
    (`@a`宛て、=全員に届く`title`/`playsound`)も同様に無効化される**
    (`commands.js`の`broadcastEffect()`)。これらは元々Botの行動では発生しない
    (Botの擬似プレイヤーは`runCommand`が無効化されている)が、OP自身やスペクテイターが
    操作した場合には発生するため、「試合を見ている誰にも何も見えない/聞こえないように
    したい」場合はこの設定も併せて無効化するとよい。**ターン開始時に各国家へ個別送信される
    「都市のターン報告」(生産完了・成長・飢餓・研究進捗などの要約)も同様に無効化される**
    (`turns.js`の`processPlayerTurnStart`)。Botはこの報告を`civs.js`の
    `getCivStorageHandle`経由でBotの追加者(コントローラー)へ転送する仕組みのため、
    `world.sendMessage`を経由しないこの経路もこの設定の対象に含めている(そうしないと、
    Botを追加したOPにだけターン報告が届き続けてしまう)。**勝利メッセージ(ソロ/宗教/同盟勝利、
    デバッグ即時勝利)、および「ゲームがリセットされました」メッセージ(実行者名入り、
    下記参照)はこの設定に関わらず常に表示される**(`turns.js`/`commands.js`/`ui.js`が
    `broadcast()`を使わず`world.sendMessage()`を直接呼んでいるため)。全員Bot同士の対戦を
    放置・高速進行させたい時に、チャット欄・画面演出が埋め尽くされるのを防ぐための設定。

  いずれも `civ:matchSettings` に保存され、**ゲームリセットを跨いでも保持される**
  (マップ・ターン状態とは異なり、resetAllで消去されない)。
- **OP専用: マップ生成の設定**(「§e[Settings] マップ生成の設定」、`mapGen.js`/`state.js`):
  まず「設定を編集する」「初期値に戻す」を選ぶハブ画面が開く。
  - 「設定を編集する」で、`/civ:generate`(§1)で使う各バイオームの生成有無・生成しやすさ
    (重み)、資源の出現率を変更できる。設定してもマップは自動で再生成されないため、
    反映させるには改めて `/civ:generate` を実行する必要がある。
  - 「初期値に戻す」は確認ダイアログを挟んだ上で、下記の全設定を既定値
    (`DEFAULT_MAP_GEN_SETTINGS`)に一括で戻す。
  - 平地系の6バイオーム(草原・森林・熱帯雨林・砂漠・寒冷地・山)は、それぞれ「生成する
    (トグル)」と「生成しやすさ(重み、0〜50)」を設定できる。無効にしたバイオームは
    マップ上に一切出現しなくなる。重みが大きいほど、他の有効なバイオームに対して
    相対的に出現しやすくなる(全て無効化するなど異常な設定にしてしまった場合は、
    生成が完全に止まらないよう自動的に草原へフォールバックする)。
  - 川・海は専用のアルゴリズム(乱歩・クラスタ配置)で生成されるため、平地系と同じ重みの
    仕組みは使わないが、同じUIで「生成する」トグルと「生成しやすさ」を設定でき、
    既定の重み(川8・海10)に対する倍率として生成量に反映される(0にする、または
    無効にすると一切生成されない)。池・湖・山脈は、それぞれ川・山の生成結果から
    自動的に派生する地形のため、個別の設定項目は無い(川を無効化すれば池・湖も、
    山を無効化すれば山脈も連動して生成されなくなる)。
  - 資源の出現率(%、0〜100、5刻み): 各マスに戦略/高級/ボーナス資源(§2)のいずれかが
    配置される確率。既定値は25%。
  いずれも `civ:mapGenSettings` に保存され、試合の設定と同様に**ゲームリセット/マップの
  再生成を跨いでも保持される**。
- **OP専用デバッグメニュー**(ゲーム進行中のみ):
  - 「指定した国家を即座に勝利させる」(§16参照)。
  - 「このマスを編集する」: 今立っているマスの状態を、通常の建設条件・技術条件を一切無視して
    直接書き換えられる(地形/資源/基礎産出量、所有者、都市の各種パラメータ、施設、区域、
    戦闘ユニット、宗教ユニット、宗教的圧力)。動作確認・デモ用。
    - このマスの所有国家がいれば「研究/社会制度を編集」も選べる。技術ツリー/文化ツリーの
      各項目を一覧表示し、タップするだけで前提条件・コストを一切無視して取得済み⇔未取得を
      直接切り替えられる(`progression.js` の `getProgressState`/`saveProgressState` を
      そのまま使用。取得中の項目を取得済みにした場合は進行中状態を解除する)。
  - 「全国家の情報を閲覧する」: ゲームに参加済みの全国家(人間・テスト国家・Bot問わず)から
    1つを選び、詳細情報を一括で閲覧できる(参照専用、書き換えは不可)。資源(石油・鉄・馬・
    ゴールド・石炭・ウラン・CO2累計排出量・勝利ポイント・開拓権)、研究/社会制度の進行状況と
    取得済み一覧、宗教の創始状況、
    保有する全都市(人口・住宅・産出量・生産中の物・区域建設状況・**都市ごとの宗教的圧力の
    内訳**。通常のメニューで都市のマスに立った時と同じ内容)、保有する全戦闘ユニット
    (位置・HP・戦闘力・移動力)、他の全国家との外交関係、を1画面にまとめて表示する。
- **ページ分割**: 選択肢が多くなりうるメニュー(ユニット移動先・攻撃対象・自分のユニット一覧)は、
  1ページ10件までに自動分割される(フォームを開く際の重さ・固まりを防止するため)。

## 19. スラッシュコマンド一覧

**2つの入り口がある**(`commands.js`):

1. **本物のカスタムスラッシュコマンド**(`registerCustomCommands()`): `/civ:settle` のように
   コマンドごとに独立して登録され、コマンド名・列挙型の引数(生産物ID・施設IDなど)ともに
   バニラのコマンドUIでタブ補完/候補表示が効く。列挙型は `PRODUCTION_DEFS` などの定義から
   自動生成しているため、新しい生産物・施設・区域を増やしてもここのコードは変更不要。
2. **`/scriptevent` 経由**(`registerScriptCommands()`): `/scriptevent civ:cmd settle` の
   ように、`civ:cmd` というIDのスクリプトイベントへ文字列引数を渡す従来からの入り口。
   入力補完は効かないが、コマンドブロック/ファンクションなど `/scriptevent` を使う場面向けに
   そのまま残している。

どちらも同じ `cmd*` 関数(commands.js)を呼び出すので、挙動は完全に同一。

> ⚠️ **カスタムコマンドの定義は `/reload` だけでは更新されない**(Bedrock側の既知の制約:
> 登録済みコマンドの引数構成を reload 中に変更しようとすると失敗する)。コマンド定義を
> 変更した場合は、ワールドを一度抜けて入り直す(またはワールドを新規作成する)必要がある。
> 登録は1コマンドずつ try/catch で独立させてあるので、reload時にこの制約に当たっても
> 他のコマンドの登録が巻き添えで失敗することはない。

## 21. 既知の制約・設計メモ

- Script APIにはワールドの実際のシミュレーション距離設定を取得する手段が無いため、
  `mapGen.js` の `ASSUMED_SIMULATION_RANGE_BLOCKS` は保守的な仮定値。ワールド設定に応じて
  調整可能。
- オフラインの実プレイヤーの `DynamicProperty` は読み書きできない(Bedrock Script APIの制約)。
  外交・研究などの処理は、対象がオフラインの場合はスキップされる。
- `/civ:start` は研究・文化・外交・首都フラグ・宗教(創始状態/名前/購入回数/審問状態)・
  戦略資源在庫をリセットするが、**勝利ポイントはリセットしない**(意図的な仕様。レート的な値
  として扱うため)。
- 産出量計算(`getCityCurrentYields`)は「人口の数だけ、優秀なマスから自動で働かせる」方式。
  建造物・施設の隣接ボーナスは人口に関係なく常時加算される。
- テスト国家(仮想国家)のデータは `/civ:end` / ゲームリセットでは消えず、ワールドに残り続ける
  (何度でも `/civ:join` し直せる)。**ただしBot(isBot:true)は例外で、`/civ:end`・デバッグ
  即時勝利・通常の勝利(ソロ/宗教/同盟)による自動リセットのいずれでも自動的に削除される**
  (`turns.js` の `resetGameState`、`civs.js` の `removeAllBots`)。対戦のたびにOPがBotを
  手動で片付ける手間を省くための挙動で、手動で追加したテスト国家(isBot:false)は対象外
  (OPが意図的に残している可能性があるため)。国家管理メニューからの手動削除(§18)は、
  ゲーム開始後はできない制約があるのと違い、この自動削除はゲームの終了そのものに伴う処理
  のため常に行われる。
- **ゲーム内表示(チャット・アクションバー・メニューのbody/button/title)に絵文字は使わない**。
  Minecraft Bedrockのデフォルトフォントは大半の絵文字グリフを描画できず豆腐(□)になるため、
  既存の `[Worker]`/`[Food]`/`[Missile]` などと同じ `[英単語]` 形式のブレースタグで代替する
  (`§`カラーコードは絵文字ではないのでそのまま使ってよい)。コード中のコメント(`💡`など)は
  開発者向けで実際には表示されないため対象外。
- カスタムスラッシュコマンド(§19)の定義変更は `/reload` では反映されない。ワールドを
  一度抜けて入り直す必要がある(Bedrock側の既知の制約)。
- `TextPrimitive`(マス上のユニット表示、`unitLabels.js`)はワールドの「ベータAPI」実験的機能が
  無効だと使えない。その場合は例外を捕まえて機能全体を静かに無効化するだけで、他の機能には
  一切影響しない。
- 産出量の倍率(§6)は `turns.js` の1箇所(`getCityCurrentYields`)でだけ適用され、実際の値は
  `state.js` の試合の設定(`getMatchSettings().yieldMultiplier`, 既定`2`)から読む。
  §8〜§12 に書かれている各ボーナスの数値は、この倍率を掛ける前の基礎値。
- 国家を操作中の「仮想プレイヤー」(`getActingPlayer()`, civs.js)は、実プレイヤーを `Proxy` で
  ラップして id/name/DynamicProperty だけを差し替えたもの。`location`/`dimension`/
  `sendMessage` などのネイティブなプロパティ・メソッドは、常に実プレイヤー本体に委譲される
  (以前は `Object.create` によるプロトタイプ委譲だったが、ネイティブ側が実体を正しく認識できず
  `sendMessage` やゲッターが失敗する不具合があったため `Proxy` に置き換えた)。
- `bots.js` は `commands.js` の `cmdClaim`/`cmdSettle` などを呼ぶために `commands.js` を
  import し、`commands.js` 側もゲーム開始/ターン終了のたびにBotへ手番を回すため `bots.js` を
  import する(意図的な相互import)。どちらの呼び出しも関数本体の中(全モジュールの読み込みが
  終わった後に実行される)でしか行われないため、ESモジュールの仕様上安全に解決される。
  ゲーム開始・ターン終了・強制ターン終了は、必ず `bots.js` の Auto版(`startGameAuto`/
  `endTurnAuto`/`forceEndTurnAuto`)経由で呼ぶこと。`turns.js` の素の関数を直接呼ぶと、
  手番がBotに回ってきたときにBotが行動せず止まったままになる。

## 22. 最近の実装改善

`state.js` のマップ状態保存について、Dynamic Property の不要な読み書きを減らすためのキャッシュを導入している。

- `getTiles()` はワールドの Dynamic Property から全タイルを毎回読み直さず、初回読み込み後はメモリ上のキャッシュを利用する。
- `setTiles()` は各行の内容を比較し、変更されていない行の Dynamic Property を書き直さない。
- `setTile()` はマップ全体を書き戻さず、変更対象の1行だけを保存する。
- `getStateVersion()` で状態変更の世代番号を取得できるため、今後の計算結果キャッシュの無効化にも利用できる。
- マップ設定変更やゲーム全体のリセット時には、関連するキャッシュを破棄して保存状態との不整合を避ける。

この改善は、特に `getTiles()` が短い間隔で呼ばれる処理で、同じ Dynamic Property を繰り返し読み込む負荷を抑えるためのもの。
ただし、都市産出量などの計算自体をキャッシュするものではなく、今後の最適化とは分けて扱う。

## 23. ゴールド

国家単位で貯まる通貨。石油・鉄・馬と同じ「戦略資源」の枠組み(`turns.js` の
`STRATEGIC_RESOURCES`、Dynamic Property `strategic_gold`)を流用しているが、他の戦略資源と
違い**マイナスの残高を許容する**(破産、後述)。

### 産出

都心(都市タイル自体)は、隣接マスや施設の有無に関係なく毎ターン基礎ゴールド+3を産出する
(信仰力が人口比例で自動的に付くのと同様、都市が存在するだけで得られる基礎収入)。
これに加えて、施設「キャンプ」「プランテーション」(§9)もゴールドを産出する(市場は
対象外)。どちらも技術「貨幣経済」が前提で、毎ターンゴールド+3(基礎値。§6の産出倍率が乗る)。

高級資源(ダイヤモンド・金・魔晶石・月の石。§2)があるマスも、労働者が割り当てられていれば
(=そのマスが実際に働かれていれば)施設不要で毎ターンゴールド+3を産出する。

交易所(§10「交易路について」参照)も、接続中の交易路ごとに国家単位でゴールドを産出する
(自国内+1、他国との対外交易は+2)。`getCityTradeBonus`経由で接続元・接続先どちらの都市の
`getCityCurrentYields(...).gold`にも織り込まれるため、下記の都市別ゴールド内訳表示にも
「その他」の差分として現れる(以前は都市単位の産出量計算を経由せず国家全体の`strategic_gold`に
直接加算していたため、HUD/ゴールド内訳のどちらにも交易収入が一切反映されないバグがあった)。

### 産出の内訳表示

`turns.js` の `getCityGoldBreakdown(cityKey, tiles)` が、都市のゴールド産出量を「都心の基礎値」
「高級資源(マス数×3)」「施設(キャンプ/プランテーション等のflatYields.gold合計)」「その他
(交易路のゴールドボーナスなど、まだ内訳化していない産出源との差分)」に分解して返す。合計は
必ず `getCityCurrentYields(...).gold` と一致する。`formatGoldBreakdownText()` で「都心+3、
高級資源x2+6」のような表示用テキストに整形し、
メインメニューの都市情報・アクションバー(足元の都市の産出が1以上のとき)・OPデバッグの
「全国家の情報を閲覧する」の都市一覧に表示される。

### 維持費(upkeep)

自分のターン開始時、`turns.js` の `calculateGoldUpkeep()` が国家全体の維持費を機械的に算出し、
ゴールド残高から差し引く(個々のユニット/建造物に維持費の値を持たせるのではなく、既存の
`cost` やフラグから計算する)。

| 対象 | 維持費 |
|---|---|
| 戦闘ユニット(`tile.combatUnit`、1体につき) | `max(1, ceil(生産コスト ÷ 30))` (例: 戦士(30)→1、戦車(300)→10) |
| 建造物(生産キュー式、区域専用建造物含む。1つにつき) | 1(既定値。区域専用建造物は個別に上書きできる。工場=2、発電所3種=3。§24) |
| 区域(district、1マスにつき) | 1 |

施設(facility)には維持費がかからない。労働者(`workerUnits`、§7)・宗教ユニット
(`tile.religiousUnit`、§11)は `tile.combatUnit` ではないため対象外。

### ゴールドでの即時購入(ラッシュバイ)

`/civ:rushbuy`(またはメインメニューの「[Gold] ゴールドで即時完成」)で、足元の自都市が
生産中(`city.production`)の物を、残りの必要生産力 × 3 ゴールドを消費して即座に完成させる。
内部的には通常のターン経過による完成と全く同じ完成処理(`tickProduction`)を直接呼ぶだけなので、
資源消費(§8)や配置失敗時の中止などの挙動もそのまま適用される。**区域(district)の建設には
使えない**(city.production限定)。蓄積済みの生産力が既にコスト以上(残り必要生産力が0)の
場合は、そもそも自然完了を待つだけで購入の必要が無いため実行できない。

### 他国家への贈与

`/civ:giftgold <国家ID> <金額>`(またはメニューの外交画面の「[Gold] ゴールドを贈る」)で、
相手の承諾を必要としない一方的な贈与ができる(戦争中でも可能)。提案/承認が必要な不可侵条約・
同盟(§15)とは別系統の、単純な残高移動。

### 破産(強制解散)

自分のターン開始時、維持費差し引き後のゴールド残高が0未満なら、**マイナス10ごとに1体**、
自国の戦闘ユニット(`tile.combatUnit`)を生産コストの安い順に強制解散する
(`applyGoldBankruptcy`)。解散は毎ターン残高がマイナスである限り繰り返される。労働者は
`tile.combatUnit` ではなく都市の `workerUnits`(§7)として保持されるため、宗教ユニット
(`tile.religiousUnit`、別レイヤー)と同様に維持費の集計対象にも解散対象にもならない
(§7・§11参照)。

## 24. 工業地帯の電力インフラ

区域「工業地帯」(§10)専用の建造物として、工房・工場・発電所3種(石炭火力/石油火力/原子力)を
追加(いずれも `DISTRICT_BUILDING_DEFS`、`forDistrict: "industrialZone"`)。工場・発電所の効果は
**常に自国の都市のみ**が対象(隣接していても他国の都市には一切影響しない)。処理は `turns.js` の
`applyIndustrialInfrastructure()` が毎ターン(そのプレイヤーの手番開始時)まとめて行う。

### 石炭・ウラン(新しい戦略資源)

石油と同じ枠組み(`STRATEGIC_RESOURCES`)で追加。専用施設は無く、資源のあるマスが労働者に
割り当てられていれば毎ターン自動で `strategic_coal`/`strategic_uranium` に収入が積まれる(§2・§6)。

- ウランは、ミサイル・対空砲(§8・§17)の生産完了時にも1消費される(在庫が無ければ他の資源
  消費ユニットと同様、生産は完了扱いのまま配置/効果適用だけ中止され、進行度は保持される)。
- 石炭は、石炭火力発電所の燃料以外に使い道はない。

### 発電所の1つ選択制

石炭火力・石油火力・原子力の3つは互いに排他(`exclusiveGroup: "powerPlant"`)。同じ工業地帯に
同時に有効化できるのは1つだけだが、別の発電所を選んで建設完了すれば古い方は自動的に無効化され
建て替えられる(値引きなし、満額コストでの再建設)。工房・工場は排他ではなく、工業地帯1つに
工房・工場・発電所のいずれか1つを同時に保有できる。

### 発電・電力供給・CO2(毎ターン自動処理)

各発電所は毎ターン、所属都市の所有者が持つ燃料資源を1消費して発電する:

| 発電所 | 燃料 | 発電量 | CO2排出量/ターン | 自都市への直接ボーナス |
|---|---|---|---|---|
| 石炭火力発電所 | 石炭 | 4 | 6(大量) | 生産力+4 |
| 石油火力発電所 | 石油 | 4 | 3(中程度) | 生産力+3 |
| 原子力発電所 | ウラン | 16 | 1(少量) | 生産力+5、科学力+4 |

燃料の在庫が1未満の場合、その発電所は**その発電所は今ターン発電しない**(電力供給・自都市への
直接ボーナス・CO2蓄積のすべてがスキップされ、ターン報告に燃料不足の警告メッセージが出る)。

発電された電力は、発電所のマスに隣接する(周囲8マス)**自国の都市すべて**に、発電量ぶんそのまま
供給される(複数の都市に隣接していれば、各都市がそれぞれ満額受け取る。分割はしない)。

CO2排出量は `strategic_co2`(国家単位のDynamic Property)に単純加算される。他国とは独立した
国家単位の値で、自国のCO2が自国の環境に跳ね返る形の環境ペナルティとして反映される:
`getCityCurrentYields()` が、その国家のCO2蓄積量50につき自国の全都市の食料産出-1する
(最大-5でそれ以上は悪化しない。倍率適用前のfoodから引くため、§6の産出倍率が他の産出量と
同じく自動的に乗る)。

### 電力の詳細表示

各都市が今受け取っている電力量とその内訳は、`applyIndustrialInfrastructure` が毎ターン
`city.powerReceived`(合計値)・`city.powerSources`(`{ plantLabel, fromCityName, amount }` の配列。
どの都市のどの発電所から何電力受け取っているか)へ書き込み直す(供給が無い都市は0/空配列に
リセットされる)。メインメニューの自都市情報、およびOPデバッグの「全国家の情報を閲覧する」の
都市一覧に、受電量が1以上か工場を持つ都市に限って表示される(§18)。

### 工場のボーナス

工場は、工場のマスに隣接する自国の都市すべてに、固定+3の生産力ボーナスを与える。さらに、
工場の**帰属都市**が(上記の電力供給によって)受け取っている電力量2につき、追加で+3される
(`bonus = 3 + 3 * floor(受電量 / 2)`)。帰属都市自身が工場に隣接していれば、その都市にも
同じ計算式でボーナスが乗る(特別扱いはしない)。

### 原子力発電所の老朽化とメルトダウン事故

原子力発電所は `city.nuclearPowerPlantAge` を毎ターン+1する(発電の成否に関わらず、存在するだけで
進む)。毎ターン、その経過ターン数に応じた確率(`min(100, 経過ターン数 × 2)` %。ui.jsの
リスク%表示と同じ式)でメルトダウン事故を抽選する。発生した場合:

- 都心のHPが半分減少する(`Math.max(1, ...)` で必ず1以上は残る。この事故単体で都市が
  陥落することはない)。
- 人口が1減少する(同じく最低1は残る)。
- 原子力発電所そのものが失われる(`city.nuclearPowerPlant = false`。再建は満額コストの
  新規建設)。
- 全プレイヤーに `broadcast()` で通知される。

プロジェクト「原子炉の再稼働」(`production.js` の `PRODUCTION_DEFS.reactorRestart`、通常の
生産メニューの建造物枠から選択、コスト300)を完了すると、老朽化年数を0にリセットして
メルトダウンの確率を下げられる。原子力発電所を保有していないと着工できない(汎用フィールド
`requiresBuildingFlag` の初使用例。`canStartProduction` が `city[id]` を直接見て判定する)。
何度でも実行できる(`uniquePerCity` は付けない)。

Botも、自国の原子力発電所の事故率が30%以上に達すると(`bots.js` の
`BOT_REACTOR_RESTART_RISK_THRESHOLD`)、通常の生産優先度より先に「原子炉の再稼働」を
自動的に選択する(`pickProductionChoice` の先頭で判定)。

## 25. 航空戦

航空ユニット(支援偵察機・支援防御機・戦闘機・戦略爆撃機、§8)は、陸軍/海軍ユニットと違って
**マス上を移動しない**。都市の**航空基地**に配置され、そこから直接出撃・略奪する
(Civilization VIの航空基地の考え方を踏襲。管理は `airbase.js` が一手に担う)。

### データの持ち方

- `city.airbase.units = []` … その都市の航空基地に配置中の航空ユニットの配列
  (`tile.combatUnit` のような単一スロットではなく、複数機を1つの都市にまとめて置ける)。
- 個々のユニットは `{ id, label, hp, maxHp, unitClass: "air", airRole, rangedCombatStrength,
  meleeCombatStrength, interceptCombatStrength?, movement, attackRange, domain: "air",
  ownerId, ownerName, patrol, actedThisTurn, interceptedThisTurn }` の形を持つ。
  `airRole` は `"recon"|"defense"|"fighter"|"bomber"`。`interceptCombatStrength` は
  戦略爆撃機だけ持たない(哨戒不可の目印)。
- `movement` は出撃距離ではなく**移設(rebase)時の航続距離**、`attackRange` は拠点から出撃
  できる**攻撃射程**として使われる(既存の `getAttackRange` をそのまま流用)。

### 航空基地の空き枠

| 供給源 | 空き枠 | 備考 |
|---|---|---|
| 都心 | +1 | 都市が存在する限り常に付与される基礎枠 |
| 飛行場(区域専用建造物、§10) | +8 | 工業地帯限定、前提技術「航空力学」 |
| 滑走路(施設、§9) | +3(1つにつき) | 帰属都市(`belongsToCityKey`)が一致する滑走路の数だけ加算 |

合計枠は `airbase.js` の `getAirbaseCapacity(city, cityKey, tiles)` がその場で算出する
(専用のキャッシュ値は持たず、必要な箇所で毎回計算する軽量な処理)。空き枠が無い状態で
航空ユニットの生産が完了すると、他の配置失敗(陸軍の「周囲に空きマスが無い」等)と同様に
生産が中止され、進行度は保持される(`cancelReason: "noAirbaseCapacity"`)。

### 出撃(攻撃)

`cmdAirStrike`(`commands.js`)。拠点(baseTx, baseTz)から攻撃距離内にある敵ユニット/敵都市を
直接攻撃する(既存の `getAttackableTargets`/`getAttackableCityTargets` を拠点座標基準で
そのまま再利用)。通常の戦闘解決は陸海軍と全く同じ計算式(`resolveCombat`/`resolveCityAttack`、
§13)を使う。1ユニット1ターン1回まで(`actedThisTurn`)。

### 迎撃(2段構え)

出撃(攻撃・略奪)は、通常の戦闘解決の前に以下の順で迎撃判定を受ける
(`commands.js` の `tryInterceptAirStrike`):

1. **対空砲(`antiAir`、§17)**: 既存の `findInterceptingAntiAirCity` を共用。範囲内に未使用の
   対空砲があれば**確実に撃墜**され、出撃自体が不発になる(反撃・ダメージ計算は一切発生しない)。
2. **哨戒中の空軍ユニット**: 対空砲が見つからなかった場合のみ、`airbase.js` の
   `findInterceptingPatrolUnit` が、目標マスから拠点までの距離が `AIR_PATROL_INTERCEPT_RADIUS`
   (1マス)以内で、かつ哨戒状態(`patrol: true`)かつ今ターン未使用(`interceptedThisTurn: false`)
   の迎撃ユニットを、`interceptCombatStrength` が最も高いもの1体だけ選ぶ。見つかれば
   `resolveAirPatrolInterception`(`combat.js`)が、対空砲とは違い**迎撃側の戦闘力で
   一方的にダメージを与えるだけ**(迎撃側はダメージを受けない)。撃墜できれば出撃は不発、
   撃墜できなければダメージを負ったまま出撃(攻撃/略奪)が続行される。
   支援偵察機(`airRole: "recon"`)は自身は哨戒できないが、同じ拠点に配置されているだけで
   迎撃ユニットの `interceptCombatStrength` に `RECON_INTERCEPT_SUPPORT_BONUS`(+10)を与える。

戦略爆撃機は哨戒できない(`interceptCombatStrength` を持たない)。

### 哨戒の切り替え

`cmdSetAirPatrol`。戦略爆撃機・支援偵察機以外は、いつでも哨戒のON/OFFを切り替えられる
(`actedThisTurn` を消費しない)。

### 略奪(戦略爆撃機のみ)

`cmdAirPillage`。HPが最大値の`PILLAGE_MIN_HP_RATIO`(50%)以上残っている場合のみ実行できる。
攻撃距離内の敵国の領有マスを対象に:

- マスに施設(§9)があれば、その施設を破壊する(`tile.facility = null`)。
- マスに完成済みの区域(§10、建設中は対象外)があり、帰属都市がその区域向けの区域専用建造物を
  保有していれば、そのうち1つを無効化する(`city[id] = false`。`exclusiveGroup` を持つ
  発電所の切り替え(§24)と同じ `onReplaced` フックを流用)。

陸軍の略奪と異なり、戦利品・ゴールドは一切得られない(ダメージを与えるだけの妨害目的)。
1ユニット1ターン1回まで(`actedThisTurn`。出撃と共有)。

### 移設(rebase)

`cmdRebaseAirUnit`。航続距離(`movement`)以内にある自国の別の航空基地(空き枠が必要)へ、
ユニットをそのまま移す(マス上の経路探索は行わない、瞬間的な拠点間の付け替え)。1ユニット
1ターン1回まで(`actedThisTurn`。出撃・略奪と共有)。

### ターン終了時の回復

`airbase.js` の `resetAndHealBasedAirUnitsForTurn(playerId, tiles)` を、そのプレイヤーの
手番開始時(`processPlayerTurnStart`)に呼ぶ。**前ターン行動しなかった**(`actedThisTurn`が
`false`のまま、迎撃で使われた場合も「行動」扱いになる)ユニットだけ、`getAirHealAmount(city)`
ぶん回復する(飛行場のある都市は`AIR_HEAL_AIRPORT`=40、無ければ`AIR_HEAL_BASE`=20)。
同じタイミングで `actedThisTurn`/`interceptedThisTurn` を新しいターン向けにリセットする
(`patrol` は持ち越す)。

### 都市の占領・消滅との関係

- 都市が占領される(`cmdCaptureCity`)と、その航空基地に配置中だった旧オーナーの航空ユニットは
  地上で捕捉されたものとして**全機撃墜**扱いになる(マス上に存在しないため、占領側が引き継ぐ・
  逃げる、といった選択肢は実装していない)。滑走路・飛行場そのものは他の施設/区域と同じく
  占領側にそのまま引き継がれるため、次に生産する航空ユニットからは通常通り使える。
- 都市が消滅する(`destroyCity`。ミサイル着弾・食料不足による崩壊)と、その都市オブジェクト
  ごと航空基地も失われる(他の都市データ同様、特別なメッセージは出ない)。

### UI

メインメニューの「航空部隊一覧」(`ui.js` の `openAirbaseUnitsMenu`)から、全都市の
配置中ユニットをまとめて一覧・操作できる(`openMyUnitsMenu`と同じく、その場にいる必要は無い)。
選択すると出撃/略奪/哨戒切り替え/移設のアクションメニュー(`openAirUnitActionMenu`)を開く。
出撃・略奪・移設の対象選択画面は、既存の移動/攻撃メニューと同じ「モニター風グリッド表示」
(§18)にも対応しており、プレイヤー個人の設定(メインメニューの「ユニット操作を〜に切り替える」、
`UNIT_ACTION_UI_STYLE_KEY`)ひとつで戦闘/宗教/航空ユニットすべての文字リスト版/モニター版が
一括で切り替わる。拠点(都心タイル)を中心とした範囲を表示し、出撃・略奪先は赤色の
`attack_target`マーカー、移設先はミント色の`move_reachable`マーカーで強調する(航空ユニット
自体はマス上に存在しないため、マス上に描画されるのはあくまで対象・移設先のマーカーのみ)。

**航空基地の空き枠(容量)を確認できる場所**は次の3箇所:
- 「航空部隊一覧」を開くと、冒頭に自国の全都市ぶんの空き枠(`使用数/容量`)が一覧表示される。
- ユニット生産メニュー(`openProductionCategoryMenu`)で、戦闘機/爆撃機/支援偵察機/支援防御機
  のボタンにその都市の空き枠が併記される。空き枠が無い場合はボタン自体が「航空基地の空き枠が
  ありません」という理由付きの非活性表示に変わる(`canStartProduction`のメッセージをそのまま表示)。
- 移設(Rebase)メニュー(`openAirRebaseMenu`)では、移設先候補となる自国都市ごとに空き枠を表示する。

### 既知の制約

- 空母(carrier)による洋上基地は未実装(このMODに空母ユニット自体が存在しないため)。
- このアップデート以前に生産されていた戦闘機/爆撃機(`tile.combatUnit`に直接配置される旧方式)
  とのセーブ互換は無い(移行ツールなし。§21と同じ「ワールドをまたぐ互換性は保証しない」方針)。
  導入時は新しいゲームから始めることを推奨する。
- Botはこのシステムに未対応(航空ユニット・飛行場・滑走路のいずれも自発的には生産しない。
  `bots.js`の生産優先度リストに未追加のため)。手動(人間プレイヤー)でのみ運用できる。
